## 문제

AI 프롬프트와 노션·PPT·엑셀 템플릿 같은 디지털 상품은 등록, 버전 관리,
주문, 결제, 정산까지 서로 다른 업무 흐름을 함께 다뤄야 합니다. PromptHub는
이 과정을 하나의 마켓플레이스로 연결하는 팀 프로젝트입니다.

## 제약

- 인증과 권한 검증은 모든 서비스에서 일관되게 처리되어야 합니다.
- 주문·결제·정산은 실패가 다른 서비스로 전파되지 않도록 분리해야 합니다.
- 상품과 판매자 정보 조회는 서비스 간 통신 비용과 데이터 일관성을 함께 고려해야 합니다.

## 검토한 선택지

하나의 애플리케이션으로 모든 기능을 처리하면 초기 구현은 단순하지만,
결제·주문·정산처럼 변화 주기와 실패 특성이 다른 기능의 영향을 분리하기
어렵습니다. 서비스 경계를 나누고 동기·비동기 통신을 용도에 따라 조합해
각 기능의 책임과 장애 범위를 명확히 하기로 했습니다.

## 선택과 구현

Spring Cloud를 기반으로 API Gateway, 서비스 디스커버리, 설정 서버와 도메인
서비스를 구성했습니다. Gateway는 RS256 JWT를 검증한 뒤 사용자 식별자와 역할을
다운스트림 서비스에 전달합니다. 서비스 간 즉시 조회에는 gRPC를, 주문·상품·결제
상태 변화에는 Kafka 이벤트를 사용했습니다.

Toss Payments 결제·환불 흐름과 Spring Batch 기반 판매자 정산을 분리하고,
주문 서비스에는 Outbox Relay를 두어 비동기 이벤트 발행을 안정적으로 처리하도록
구성했습니다. 자세한 구현은 [GitHub 저장소](https://github.com/oxix97/beadv6_6_3JMT_BE)에서
확인할 수 있습니다.

## 결과

현재 개발 중인 팀 프로젝트입니다. 인증, 상품, 주문, 결제, 정산의 경계를
분리한 구조를 바탕으로 마켓플레이스의 핵심 흐름을 구현하고 있으며, 이후에는
서비스별 운영 지표와 장애 대응 절차를 보완할 계획입니다.
