## 문제

개발 블로그, 공부 기록, 회고, 프로젝트, 이력서가 흩어져 있으면 방문자는
개발자의 강점과 성장 과정을 한 흐름으로 이해하기 어렵습니다. 작성자에게도
각 플랫폼의 편집 방식이 달라 기록이 끊기기 쉽습니다.

## 선택지

Docusaurus는 문서 구조와 React 생태계가 강하지만 개인 사이트에는 런타임과
구조가 상대적으로 무겁습니다. Astro는 정적 HTML 중심이고 Starlight를 통해
문서 탐색과 검색을 얻을 수 있어 이번 목적에 더 잘 맞았습니다.

## 선택과 구현

Astro의 커스텀 홈 화면과 Starlight의 문서 영역을 결합했습니다. 콘텐츠는 한
개의 검증된 `docs` 컬렉션에 두고 폴더가 URL과 탐색 구조를 결정합니다.
Starlight Obsidian 테마의 그래프와 백링크로 서로 관련된 글을 연결합니다.

## 결과와 다음 단계

새 글은 Markdown 파일을 추가하고 Git으로 push하면 게시되는 단일 흐름을
가집니다. 빌드 검증과 GitHub Pages 배포를 자동화한 뒤, 실제 글이 늘어나면
태그별 탐색과 프로젝트 성과 지표를 보강할 계획입니다.

이 프로젝트의 기록 원칙은
[기술적 의사결정을 기록하는 이유](/blog/recording-technical-decisions/)에서
확인할 수 있습니다.
