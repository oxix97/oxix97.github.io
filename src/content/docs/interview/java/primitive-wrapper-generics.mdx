<details class="interview-question">
<summary>31. 기본형과 참조형의 차이는 무엇인가요?</summary>


### 면접 답변

기본형은 `int`, `long`, `boolean`처럼 실제 값을 직접 표현하는 타입입니다.

참조형은 객체 자체가 아니라 객체를 가리키는 참조를 저장합니다.

기본형은 null을 가질 수 없지만 참조형은 null을 가질 수 있습니다.

Java Generic이나 Collection에서는 기본형을 직접 사용할 수 없기 때문에 Integer 같은 Wrapper 타입을 사용합니다.

### 예상 꼬리질문

* 기본형은 무조건 Stack에 저장되나요?
* Wrapper를 사용하면 어떤 비용이 있나요?
* Integer와 int 중 무엇을 선택해야 하나요?

<details class="interview-question">
<summary>32. Wrapper 클래스는 왜 존재하나요?</summary>


### 면접 답변

Java의 기본형을 객체 형태로 다룰 수 있도록 제공되는 클래스입니다.

예를 들어 Generic은 타입 파라미터로 기본형을 사용할 수 없기 때문에 `List<int>` 대신 `List<Integer>`를 사용해야 합니다.

또한 null 표현이나 문자열 변환 같은 유틸리티 기능도 제공합니다.

하지만 Wrapper는 객체이기 때문에 기본형보다 메모리 사용량이나 Boxing 비용이 발생할 수 있고 null로 인한 NPE 가능성도 있습니다.

### 예상 꼬리질문

* 왜 Generic은 primitive를 지원하지 않나요?
* OptionalInt가 존재하는 이유는 무엇인가요?

<details class="interview-question">
<summary>33. Boxing과 Unboxing이란 무엇인가요?</summary>


### 면접 답변

Boxing은 `int` 같은 기본형을 `Integer` 같은 Wrapper 객체로 변환하는 것입니다.

반대로 Unboxing은 Wrapper 객체에서 기본형 값을 꺼내는 것입니다.

Java에서는 이를 자동으로 수행하는 Auto Boxing과 Auto Unboxing을 지원합니다.

편리하지만 반복적으로 Boxing이 발생하면 객체 생성 비용이 생길 수 있고 null인 Wrapper를 Unboxing하면 NullPointerException이 발생할 수 있습니다.

### 예상 꼬리질문

* Auto Boxing은 내부적으로 어떤 메서드를 사용하나요?
* null Integer를 int에 할당하면 어떻게 되나요?



</details>
<details class="interview-question">
<summary>34. Auto Boxing에서 주의해야 할 점은 무엇인가요?</summary>


### 면접 답변

첫 번째는 Wrapper 타입이 null일 수 있다는 점입니다.

예를 들어 null인 Integer가 자동 Unboxing되면 NullPointerException이 발생합니다.

두 번째는 Wrapper 객체를 `==`로 비교하는 문제입니다. Integer는 일부 값을 캐싱하기 때문에 값에 따라 `==` 결과가 다르게 나타날 수 있습니다.

마지막으로 대량 연산에서 반복적인 Boxing과 Unboxing이 발생하면 기본형에 비해 불필요한 객체 처리 비용이 생길 수 있습니다.

### 예상 꼬리질문

* Integer Cache 범위는 어떻게 되나요?
* `Integer.valueOf()`와 `new Integer()`의 차이는 무엇인가요?

<details class="interview-question">
<summary>35. Integer 비교에서 ==가 문제가 되는 이유는 무엇인가요?</summary>


### 면접 답변

Integer는 객체이기 때문에 `==`를 사용하면 값을 비교하는 것이 아니라 동일한 객체를 참조하는지를 비교합니다.

특히 `Integer.valueOf()`는 최소 -128부터 127 범위의 객체를 캐싱하기 때문에 작은 값에서는 우연히 `==`가 true가 될 수 있습니다.

반면 더 큰 값에서는 별도 객체가 생성되어 false가 될 수 있습니다.

따라서 Wrapper 타입의 값 비교에는 `equals()`를 사용하는 것이 안전합니다.

### 예상 꼬리질문

* `Objects.equals()`를 사용하는 이유는 무엇인가요?
* Long도 캐시가 있나요?



</details>
<details class="interview-question">
<summary>36. Generic을 사용하는 이유는 무엇인가요?</summary>


### 면접 답변

Generic은 클래스나 메서드가 사용할 타입을 외부에서 지정할 수 있도록 하는 기능입니다.

가장 큰 장점은 컴파일 시점의 타입 안정성을 확보할 수 있다는 것입니다.

Generic이 없다면 Object로 데이터를 저장하고 사용할 때마다 직접 형변환해야 하지만 Generic을 사용하면 컴파일러가 타입을 검증하고 불필요한 캐스팅을 줄여줍니다.

또한 동일한 자료구조나 알고리즘을 여러 타입에 재사용할 수 있습니다.

### 예상 꼬리질문

* Generic이 런타임에도 타입을 알고 있나요?
* Generic의 단점은 무엇인가요?
* Raw Type은 무엇인가요?



</details>
<details class="interview-question">
<summary>37. Generic의 Type Erasure란 무엇인가요?</summary>


### 면접 답변

Java Generic의 타입 정보 대부분이 컴파일 과정에서 제거되는 것을 Type Erasure라고 합니다.

예를 들어 `List<String>`과 `List<Integer>`는 컴파일 후 런타임에서는 기본적으로 같은 List 클래스가 사용됩니다.

컴파일러가 필요한 타입 체크와 캐스팅 코드를 삽입해 타입 안정성을 보장합니다.

이 때문에 런타임에 `new T()`를 직접 생성하거나 `List<String>.class` 같은 표현을 사용할 수 없는 제약이 있습니다.

### 예상 꼬리질문

* 왜 Java는 Type Erasure 방식을 선택했나요?
* Runtime에 Generic 타입을 알아내는 방법은 없나요?



</details>
<details class="interview-question">
<summary>38. &lt;?&gt;, &lt;? extends T&gt;, &lt;? super T&gt; 차이는 무엇인가요?</summary>


### 면접 답변

`<?>`는 타입을 정확하게 알 수 없는 모든 Generic 타입을 의미합니다.

`<? extends T>`는 T 또는 T의 하위 타입을 의미하며 주로 데이터를 읽는 Producer 역할에 적합합니다. 정확한 하위 타입을 알 수 없기 때문에 일반적으로 값을 추가하기 어렵습니다.

`<? super T>`는 T 또는 T의 상위 타입을 의미하고 T 타입 데이터를 안전하게 넣을 수 있기 때문에 Consumer 역할에 적합합니다.

이 원칙을 PECS라고 부릅니다.

### 예상 꼬리질문

* extends에서 왜 add가 불가능한가요?
* super에서 꺼낸 값은 어떤 타입인가요?



</details>
<details class="interview-question">
<summary>39. PECS 원칙이 무엇인가요?</summary>


### 면접 답변

PECS는 **Producer Extends, Consumer Super**의 약자입니다.

Generic 컬렉션에서 데이터를 읽어오는 역할이라면 `? extends T`를 사용하고, 데이터를 넣는 역할이라면 `? super T`를 사용하는 원칙입니다.

예를 들어 어떤 메서드가 Number 하위 타입의 값을 읽기만 한다면 `List<? extends Number>`를 사용할 수 있습니다.

반대로 Integer를 추가해야 한다면 `List<? super Integer>`를 사용할 수 있습니다.

### 예상 꼬리질문

* Producer에 값을 추가할 수 없는 이유는 무엇인가요?
* 실제 Java API에서 PECS 예시를 들어주세요.



</details>
<details class="interview-question">
<summary>40. Generic 배열을 직접 생성하기 어려운 이유는 무엇인가요?</summary>


### 면접 답변

배열은 런타임에도 자신의 원소 타입을 알고 있는 reified 타입입니다.

반면 Java Generic은 Type Erasure 때문에 런타임에 타입 파라미터 정보가 대부분 제거됩니다.

따라서 `new T[10]`처럼 런타임에 정확한 T 타입 배열을 생성하는 것이 불가능합니다.

또한 배열은 공변이지만 Generic은 기본적으로 불공변이라는 타입 시스템 차이도 있습니다.

### 예상 꼬리질문

* 배열이 공변이라는 것은 무엇인가요?
* Generic이 불공변인 이유는 무엇인가요?



</details>
