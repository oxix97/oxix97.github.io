## 핵심 요약

유니캐스트·멀티캐스트·브로드캐스트는 **누구에게 전달하는가**를 구분하는 전달 대상 기준이고, LAN·MAN·WAN은 **어느 정도 범위를 연결하는가**를 구분하는 통신 범위 기준이다. 따라서 사무실 LAN 안에서도 HTTP 요청은 유니캐스트일 수 있고, WAN을 지나는 통신도 유니캐스트일 수 있어 두 분류를 같은 축으로 섞으면 안 된다. 전달 대상은 수신자의 범위를, 통신 범위는 네트워크가 연결하는 지리적·운영적 규모를 설명한다.

## 전달 대상에 따른 분류

유니캐스트는 한 송신자가 한 수신자에게 보내는 일대일 전달 방식이다. 멀티캐스트는 가입하거나 지정된 그룹의 여러 수신자에게 보내는 일대다 전달 방식이고, 브로드캐스트는 같은 브로드캐스트 도메인에 연결된 모든 노드에 보내는 일대다 전달 방식이다. 즉 멀티캐스트와 브로드캐스트 모두 여러 수신자가 될 수 있지만, 전자는 특정 그룹만 대상으로 하고 후자는 연결된 전체 노드를 대상으로 한다.

전달 대상을 먼저 정하면 불필요한 수신자에게 데이터가 퍼지는지와 수신자 식별을 어떻게 하는지 판단하기 쉬워진다. 브로드캐스트는 수신 범위가 넓으므로 네트워크 세그먼트를 넘나드는 전달로 일반화해서 이해하면 안 된다. 반면 멀티캐스트는 관심 있는 수신자 그룹을 전제로 하므로, 그룹 가입과 네트워크 장비의 지원 여부까지 함께 고려해야 한다.

## 유니캐스트·멀티캐스트·브로드캐스트 비교

| 방식 | 전달 대상 | 대표적인 상황 | 설계 시 확인할 점 |
| --- | --- | --- | --- |
| 유니캐스트 | 특정 수신자 한 명 | 클라이언트와 서버 사이의 HTTP 요청·응답 | 수신자 주소, 연결 수, 개별 요청의 지연시간 |
| 멀티캐스트 | 지정된 수신자 그룹 | 같은 콘텐츠를 구독 그룹에 전달하는 네트워크 전송 | 그룹 관리, 라우터·스위치 지원, 그룹 밖 노드의 배제 |
| 브로드캐스트 | 같은 브로드캐스트 도메인의 모든 노드 | LAN에서 모든 노드가 알아야 하는 탐색·알림 흐름 | 도메인 크기, 불필요한 처리량, 브로드캐스트 폭주 가능성 |

유니캐스트는 대상이 명확해 일반적인 요청·응답 흐름에 잘 맞지만, 같은 데이터를 여러 대상에게 각각 보내면 송신량이 늘 수 있다. 멀티캐스트는 필요한 그룹에만 한 번의 전송 흐름을 전달할 수 있지만, 모든 네트워크에서 동일하게 사용할 수 있는 것은 아니다. 브로드캐스트는 수신자 사전 식별 없이 같은 도메인에 알릴 수 있으나, 대상이 커질수록 각 노드와 링크에 불필요한 부담을 줄 수 있다.

## 통신 범위에 따른 분류

LAN, MAN, WAN은 패킷을 누구에게 보낼지 정하는 방식이 아니라 네트워크가 포괄하는 범위를 설명한다. LAN은 집, 사무실, 캠퍼스처럼 비교적 제한된 장소의 근거리 네트워크이고, MAN은 도시권처럼 여러 LAN을 연결하는 범위이며, WAN은 국가·대륙처럼 넓은 지역을 잇는 광역 네트워크다. 실제 서비스에서는 이 범위가 하나의 고정된 거리만으로 정해지기보다, 소유·운영 주체, 연결 기술, 경로와 비용을 포함해 이해하는 편이 안전하다.

범위가 넓어질수록 중간 경로와 운영 주체가 많아지고, 지연시간·가용성·보안·회선 비용의 불확실성도 커질 수 있다. 그러나 WAN이라고 반드시 느리거나 LAN이라고 항상 빠르다고 단정할 수는 없으며, 실제 성능은 경로, 혼잡, 링크 품질, 서버 처리 시간으로 확인해야 한다. 범위 분류는 성능 수치를 보장하는 등급표가 아니라 설계와 운영 조건을 생각하는 출발점이다.

## LAN·MAN·WAN 비교

| 범위 | 연결하는 대상 | 일반적인 예 | 백엔드 관점의 확인 사항 |
| --- | --- | --- | --- |
| LAN | 집·사무실·데이터센터처럼 가까운 장소의 장비 | 사내 서비스와 데이터베이스가 있는 네트워크 | 스위치, VLAN, 내부 주소 체계, 국지적 장애 범위 |
| MAN | 도시권의 여러 근거리 네트워크 | 서로 다른 지사의 도시권 연결 | 사업자 구간, 회선 이중화, 지점 간 지연시간 |
| WAN | 국가·대륙 등 광역의 네트워크 | 리전 간 서비스 호출과 인터넷 경로 | 인터넷·전용선 경로, RTT, 장애 우회, 데이터 전송 비용 |

LAN에서는 IP 같은 논리 주소와 MAC 같은 링크 계층 주소를 함께 사용해 가까운 장비를 식별하고 전달한다. MAN과 WAN에서는 라우터와 사업자 네트워크를 거치는 경로가 늘어나므로, 단순한 주소 확인 외에도 경로 품질과 장애 대응 계획이 중요해진다. NAT는 제한된 공인 IP 주소를 여러 내부 장비가 공유하도록 돕는 기술이지만, LAN·MAN·WAN 자체를 구분하는 기준은 아니다.

## 백엔드 통신은 어떤 방식에 해당하는가

일반적인 REST API와 gRPC 요청·응답은 한 클라이언트가 특정 서버 또는 서비스 인스턴스와 통신하므로 전달 대상 관점에서 유니캐스트로 설명할 수 있다. 이 요청이 사내 LAN에 머무르는지, 지사 사이 MAN을 지나는지, 다른 리전이나 외부 API까지 WAN을 지나는지는 통신 범위의 별도 문제다. 따라서 같은 REST API라도 배포 위치와 경로에 따라 LAN 또는 WAN을 지날 수 있지만, 요청이 특정 수신자를 향한다는 성격은 바뀌지 않는다.

Kafka 생산자는 브로커에 레코드를 쓰고, 소비자 그룹 안에서는 파티션을 기준으로 소비자에게 메시지 처리가 분배된다. Kafka 소비자 그룹의 메시지 분배는 네트워크 계층의 IP 멀티캐스트와 같지 않으며, 브로커 기반 애플리케이션 계층의 저장·구독·파티션 할당 동작이다. 같은 토픽을 여러 소비자 그룹이 구독할 수 있다는 사실도 IP 멀티캐스트 패킷이 네트워크에서 특정 그룹으로 전달되는 방식과는 구분해서 설계해야 한다.

## 장점과 한계

전달 대상과 통신 범위를 분리하면 REST API, 실시간 알림, 이벤트 스트리밍, 리전 간 호출을 같은 용어로 성급하게 묶지 않고 각기 다른 질문을 할 수 있다. 대상 분류는 수신자 수와 전달 부담을, 범위 분류는 경로·지연·운영 조건을 살피는 데 도움을 준다.

하지만 이 두 분류만으로 실제 성능이나 보안 수준을 확정할 수는 없다. 멀티캐스트 지원 여부, 브로드캐스트 도메인, 라우팅 정책, 애플리케이션 프로토콜, 암호화와 접근 제어는 별도로 확인해야 한다. 따라서 분류는 설계 결론이 아니라 필요한 관측과 운영 질문을 정리하는 기준으로 사용해야 한다.

## 기술면접 질문

### 유니캐스트와 브로드캐스트의 차이

유니캐스트는 특정 수신자 한 명에게 전달하는 일대일 통신이고, 브로드캐스트는 같은 브로드캐스트 도메인의 모든 노드에게 전달하는 일대다 통신입니다. 일반적인 HTTP 요청·응답은 수신 서버가 특정되므로 유니캐스트 관점으로 설명할 수 있습니다. 브로드캐스트는 수신자를 미리 지정하지 않고 알릴 수 있지만 도메인이 커지면 불필요한 수신과 처리 부담이 늘 수 있습니다.

### 멀티캐스트와 Kafka 소비자 그룹의 차이

멀티캐스트는 네트워크 계층에서 특정 수신자 그룹을 대상으로 패킷을 전달하는 방식입니다. Kafka 소비자 그룹은 브로커에 저장된 레코드를 파티션 할당에 따라 소비자들이 나누어 처리하는 애플리케이션 계층의 동작입니다. 따라서 Kafka 소비자 그룹의 메시지 분배는 네트워크 계층의 IP 멀티캐스트와 같지 않고, 저장·재처리·구독 그룹이라는 별도 개념을 가집니다.

### LAN·MAN·WAN이 구분하는 기준

LAN·MAN·WAN은 데이터가 누구에게 전달되는지가 아니라 네트워크가 연결하는 지리적·운영적 범위를 구분합니다. LAN은 집이나 사무실 같은 근거리, MAN은 도시권, WAN은 국가나 대륙처럼 넓은 범위를 연결하는 맥락으로 이해할 수 있습니다. 범위가 넓어질수록 경로와 운영 주체가 늘 수 있지만 실제 지연시간과 가용성은 측정값으로 확인해야 합니다.
