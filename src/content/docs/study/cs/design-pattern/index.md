Inflearn `CS 지식의 정석` 디자인 패턴 섹션을 강의 흐름에 맞춰 8편으로 정리했다.
패턴의 정의와 싱글톤에서 시작해 생성·순회·의존 관계, 객체 간 통신, UI 아키텍처, Flux까지 이어진다.
각 글에서는 해결하려는 문제와 변경 비용, 적용할 때의 장점과 한계를 함께 살핀다.

프로그래밍이 낯설다면 문제 상황과 그림을 먼저 읽고, 각 역할이 어떤 일을 맡는지 따라가면 된다. Java를 공부하고 있다면 그림 속 역할을 코드에서 찾아보고, 표와 면접 질문으로 차이를 확인해 보자. 3편은 Java의 동시 접근과 초기화 규칙을 다루는 심화 편이므로, 처음에는 2편을 읽은 뒤 4편으로 이어 가도 된다.

## 읽는 순서

1. [디자인 패턴이란 무엇인가](./introduction/)

   결제 수단이 늘어날 때 수정 범위를 줄이는 이유와 라이브러리·프레임워크의 호출 차이를 살핀다.
2. [싱글톤 패턴의 원리와 장단점](./singleton-basics/)

   여러 기능이 같은 설정 객체 하나를 공유하는 구조와 공유하면 안 되는 상태를 구분한다.
3. [싱글톤 구현 방식 비교](./singleton-implementations/)

   두 요청이 동시에 객체를 만들 때의 문제와 Java 구현 일곱 가지를 비교한다. Java 동시성 심화 편이다.
4. [팩토리 패턴과 이터레이터 패턴](./factory-and-iterator/)

   알림 객체를 선택해 만드는 과정과 주문 목록을 하나씩 읽는 과정을 따라간다.
5. [DI·DIP와 전략 패턴](./dependency-injection-and-strategy/)

   하나의 결제 예제로 의존 방향, 객체 전달, 행동 교체가 각각 무엇인지 구분한다.
6. [옵저버 패턴과 프록시 패턴](./observer-and-proxy/)

   주문 변경을 여러 구독자에게 알리는 흐름과 실제 결제 앞에서 권한을 확인하는 흐름을 비교한다.
7. [MVC·MVP·MVVM과 Spring MVC](./mvc-mvp-mvvm/)

   이름 변경 결과를 화면에 표시하는 역할을 비교하고 서버의 HTML·JSON 응답 경로를 살핀다.
8. [Flux 패턴과 디자인 패턴 총정리](./flux-and-review/)

   메시지 목록과 배지를 함께 갱신하는 과정을 보고 해결하려는 문제별로 패턴을 복습한다.
