IP 패킷에는 목적지 IP 주소가 있는데도 이더넷 프레임에는 목적지 MAC 주소가 필요하다. 두 주소가 쓰이는 범위와 ARP가 연결하는 지점을 나눠 보면, 원격 서버의 MAC 주소를 직접 찾는다는 오해를 피할 수 있다.

## 핵심 요약

- IP 주소는 네트워크 사이에서 목적지를 식별하고 경로를 고르는 데 쓰이고, MAC 주소는 같은 링크에서 프레임을 전달할 인터페이스를 식별한다.
- ARP는 IPv4 주소에 대응하는 링크 계층 주소를 같은 브로드캐스트 도메인에서 찾는다.
- 원격 목적지로 보낼 때 호스트가 찾는 값은 원격 서버의 MAC 주소가 아니라 기본 게이트웨이의 MAC 주소다.
- MAC 주소는 흔히 48비트 EUI-48로 표현하지만, 소프트웨어로 바꾸거나 로컬 주소를 사용할 수 있으므로 불변값으로 보아서는 안 된다.
- RARP는 부팅한 호스트가 자신의 하드웨어 주소로 프로토콜 주소를 얻도록 설계된 프로토콜이다. 임의의 MAC 주소를 IP 주소로 바꾸는 일반 역조회 기능은 아니다.

## IP 주소와 MAC 주소가 모두 필요한 이유

IP 주소는 인터넷 계층의 논리 주소다. 라우터는 목적지 IP 주소와 라우팅 테이블을 비교해 패킷을 다음 네트워크로 넘긴다. 호스트의 네트워크 설정이나 접속 위치가 바뀌면 IP 주소도 달라질 수 있다.

MAC 주소는 Ethernet이나 Wi-Fi 같은 IEEE 802 네트워크에서 프레임의 출발지와 목적지를 표시한다. IEEE Registration Authority가 할당하는 주소 블록으로 만든 EUI-48은 48비트다. 보통 16진수 여섯 묶음으로 `00:1a:2b:3c:4d:5e`처럼 쓴다.

| 구분 | IP 주소 | MAC 주소 |
| --- | --- | --- |
| 주된 계층 | 인터넷 계층 | 링크 계층 |
| 판단 범위 | 여러 네트워크를 지나는 경로 | 현재 링크의 프레임 전달 |
| 대표 표기 | `192.0.2.10`, `2001:db8::10` | `00:1a:2b:3c:4d:5e` |
| 변경 가능성 | 네트워크 구성에 따라 바뀔 수 있다 | 하드웨어에 할당되기도 하지만 로컬 설정으로 바꿀 수 있다 |

MAC 주소를 물리 주소라고 부르기도 하지만, NIC에 영구히 새겨진 변경 불가능한 값이라는 뜻은 아니다. 운영체제는 locally administered address를 설정할 수 있고, 가상 인터페이스도 MAC 주소를 가진다. 제조 과정의 실수나 관리 문제로 중복될 수도 있다.

**IP 주소는 최종 목적지를 따라가지만, 이더넷 프레임의 목적지 MAC 주소는 링크를 지날 때마다 다음 전달 대상에 맞게 바뀐다.**

## ARP가 같은 링크의 MAC 주소를 찾는 과정

ARP(Address Resolution Protocol)는 IPv4 주소와 Ethernet 주소 사이의 대응을 찾는다. `192.0.2.10/24`인 호스트 A가 같은 링크의 `192.0.2.20`인 호스트 B로 패킷을 보낸다고 가정한다.

```text
호스트 A                         같은 링크                         호스트 B
192.0.2.10                                                      192.0.2.20

ARP 캐시에 192.0.2.20이 있는지 확인
        |
        |  ARP Request: "192.0.2.20은 누구인가?"
        |  목적지 MAC ff:ff:ff:ff:ff:ff로 브로드캐스트
        |---------------------------------------------------------->
        |  ARP Reply: "192.0.2.20은 bb:bb:bb:bb:bb:bb이다"
        |<----------------------------------------------------------
대응 관계를 캐시에 저장
목적지 MAC이 bb:bb:bb:bb:bb:bb인 프레임 전송
```

호스트 A는 먼저 라우팅 결과로 B가 같은 링크에 있는지 판단한다. ARP 캐시에 대응 관계가 없다면 전체 비트가 1인 Ethernet 브로드캐스트 주소로 요청을 보낸다. 요청한 IPv4 주소를 가진 B는 자신의 MAC 주소를 담아 A에 응답한다. A는 이 결과를 일정 시간 캐시에 저장하고 프레임을 전송한다.

Linux에서는 `ip neigh show`, Windows에서는 `arp -a`로 이웃 캐시를 확인할 수 있다. 캐시는 매번 브로드캐스트하지 않게 해 주지만 영구 정보는 아니다. 인터페이스 교체나 주소 이동이 있으면 항목이 갱신되거나 만료되어야 한다.

## 원격 서버로 보낼 때 ARP가 찾는 주소

호스트 A가 `198.51.100.20`처럼 다른 네트워크의 주소로 보내면 흐름이 달라진다. 라우팅 테이블은 목적지가 로컬 링크 밖에 있다고 판단하고 기본 게이트웨이 `192.0.2.1`을 다음 홉으로 선택한다.

```text
IP 패킷
  출발지 IP: 192.0.2.10
  목적지 IP: 198.51.100.20

첫 번째 Ethernet 프레임
  출발지 MAC: 호스트 A의 MAC
  목적지 MAC: 192.0.2.1인 기본 게이트웨이의 MAC
```

IP 패킷의 목적지 주소는 원격 서버를 가리킨다. 반면 첫 프레임의 목적지 MAC 주소는 기본 게이트웨이를 가리킨다. 호스트 A는 ARP로 `198.51.100.20`의 MAC 주소를 묻지 않고 `192.0.2.1`의 MAC 주소를 찾는다. 라우터가 다음 링크로 패킷을 전달할 때는 그 링크에 맞는 새 프레임을 만든다.

**ARP는 인터넷 전체의 IP와 MAC을 연결하는 디렉터리가 아니라 현재 링크에서 다음 프레임을 보낼 주소를 찾는 절차다.**

## RARP는 ARP의 일반적인 역함수가 아니다

RARP(Reverse Address Resolution Protocol)는 자신의 하드웨어 주소만 아는 호스트가 프로토콜 주소를 얻도록 설계됐다. RFC 903은 디스크가 없는 워크스테이션이 부팅할 때 자신의 IP 주소를 모르는 상황을 예로 든다. 호스트가 RARP 요청을 브로드캐스트하면 같은 매체의 RARP 서버가 미리 관리한 대응표를 보고 응답한다.

따라서 RARP를 `MAC 주소를 넣으면 어느 장치의 IP든 알려 주는 프로토콜`로 이해하면 범위가 지나치게 넓다. 요청 호스트가 자신의 주소를 초기화하는 절차에 가깝고, 라우터를 넘어 필요한 부팅 설정 전체를 전달하기에도 제한이 있다. 이후 BOOTP와 DHCP가 IP 주소뿐 아니라 게이트웨이, DNS 서버 같은 설정을 함께 전달하는 방식으로 이 역할을 대체했다.

## 장점과 한계

ARP 덕분에 애플리케이션은 같은 링크의 MAC 주소를 미리 알지 못해도 IPv4 통신을 시작할 수 있다. 응답을 캐시하면 요청 브로드캐스트도 줄어든다. IP 주소로 경로를 고르고 링크마다 필요한 MAC 주소를 구하는 구조는 라우팅과 프레임 전달의 책임을 분리한다.

반면 ARP 메시지 자체에는 응답자가 정말 해당 IPv4 주소의 소유자인지 인증하는 장치가 없다. 거짓 응답으로 캐시를 오염시키는 ARP spoofing에 노출될 수 있다. 요청은 브로드캐스트 도메인 안에서만 동작하며, 캐시가 오래된 값을 갖고 있으면 일시적인 통신 오류도 생길 수 있다. RARP는 제공할 수 있는 설정과 전달 범위가 좁아 현대 호스트 설정에는 거의 사용하지 않는다.

## 기술면접 질문

### IP 주소와 MAC 주소는 어떤 차이가 있는가?

IP 주소는 인터넷 계층에서 목적지 네트워크와 인터페이스를 식별하고 라우팅에 사용하는 논리 주소입니다. MAC 주소는 같은 링크에서 Ethernet 프레임을 전달할 인터페이스를 식별합니다. 원격 통신에서도 목적지 IP는 서버를 가리키지만, 각 링크의 목적지 MAC은 다음 홉에 맞게 바뀝니다.

### 원격 서버에 접속할 때 ARP는 어느 MAC 주소를 찾는가?

라우팅 결과가 원격 네트워크라면 호스트는 원격 서버가 아니라 다음 홉인 기본 게이트웨이의 MAC 주소를 찾습니다. IP 패킷의 목적지에는 원격 서버 주소를 유지하고, 첫 Ethernet 프레임의 목적지에는 게이트웨이 MAC 주소를 넣습니다. ARP 요청은 같은 브로드캐스트 도메인 안에서만 전달됩니다.

### RARP는 무엇이며 ARP의 역조회라고만 설명하면 왜 부족한가?

RARP는 자신의 하드웨어 주소만 아는 부팅 호스트가 RARP 서버로부터 자신의 프로토콜 주소를 얻도록 만든 프로토콜입니다. 임의의 MAC 주소에 대응하는 IP 주소를 전역에서 찾는 기능은 아닙니다. 제공할 수 있는 설정이 제한적이어서 이후 BOOTP와 DHCP가 이 역할을 대신하게 됐습니다.
