서버 응답이 도착했다고 화면이 곧바로 완성되지는 않는다. HTML 파싱과 스타일 계산, 레이아웃과 그리기가 어떤 순서로 이어지는지 보면 응답 시간과 화면 표시 지연을 구분하기 쉽다.

## 핵심 요약

- HTML 파서는 문서에서 DOM을 만들고 CSS 파서는 스타일 규칙에서 CSSOM을 만든다.
- 브라우저는 DOM과 계산된 스타일을 이용해 렌더링에 필요한 객체를 구성한다.
- 레이아웃은 요소의 크기와 위치를 계산하고, 그리기는 화면에 표시할 픽셀을 만든다.
- 합성 단계는 여러 레이어를 화면에 배치하지만 모든 요소가 별도 GPU 레이어가 되는 것은 아니다.

## HTML과 CSS에서 DOM·CSSOM을 만든다

브라우저는 HTML을 토큰과 노드로 읽어 문서 구조를 DOM 트리로 만든다. CSS 규칙은 CSSOM으로 구성되고, 상속과 우선순위 계산에 사용된다. HTML 파싱 도중 필요한 CSS·이미지·스크립트가 있으면 추가 네트워크 요청이 시작될 수 있다.

스크립트는 실행 시점과 속성에 따라 HTML 파싱을 막거나 지연시킬 수 있다. 외부 스타일도 화면에 필요한 계산을 막을 수 있어 리소스의 로딩 순서가 첫 화면 시점에 영향을 준다.

## 렌더 트리와 레이아웃을 계산한다

DOM의 모든 노드가 화면 요소가 되는 것은 아니다. 브라우저는 표시할 노드와 계산된 스타일을 바탕으로 렌더링에 필요한 구조를 만든다. `display: none` 요소는 레이아웃 대상에서 제외되지만 `visibility: hidden`은 공간을 유지한 채 보이지 않게 한다.

레이아웃 단계는 각 요소의 크기와 문서 내 위치를 계산한다. 창 크기나 글꼴, 콘텐츠가 바뀌면 레이아웃을 다시 계산할 수 있다. 큰 범위의 레이아웃 변경은 화면 갱신 비용을 늘린다.

## 그리기와 합성으로 화면을 표시한다

브라우저는 배경, 글자, 테두리 등 시각 요소를 그려 픽셀을 만든다. 일부 콘텐츠는 별도 레이어로 관리되며 합성 단계에서 적절한 순서와 위치로 화면에 배치된다.

모든 요소가 독립 레이어가 되거나 모든 그리기 작업이 GPU에서 처리되는 것은 아니다. 레이어 생성은 브라우저와 장치, CSS 효과에 따라 달라지므로 `transform`을 무조건 추가해 성능을 높인다고 가정하면 안 된다.

**DOM은 문서 구조이고 렌더링 결과는 스타일·레이아웃을 반영하므로 두 트리는 일대일 대응하지 않는다.**

## 장점과 한계

렌더링 단계를 나누면 HTML 수신이 늦은 경우와 파싱·스크립트·레이아웃 때문에 화면이 늦는 경우를 구분할 수 있다. 브라우저 개발자 도구에서 네트워크와 성능 기록을 함께 보면 병목 단계를 좁힐 수 있다.

세부 알고리즘과 레이어 구성은 브라우저 엔진마다 다르며 비동기 작업이 섞일 수 있다. 단순한 단계 그림은 원리를 설명하지만 특정 페이지의 실제 렌더 타이밍을 대신하지 않는다.

## 기술면접 질문

### DOM과 CSSOM은 각각 무엇인가?

DOM은 HTML 문서의 노드와 관계를 표현하고 CSSOM은 CSS 규칙과 계산에 필요한 스타일 구조를 표현합니다. 브라우저는 두 정보로 요소의 표시와 레이아웃을 결정합니다. HTML 노드가 모두 화면에 보이는 것은 아닙니다.

### 브라우저의 레이아웃과 그리기는 어떻게 다른가?

레이아웃은 요소의 크기와 위치를 계산하고 그리기는 색상·글자·테두리 등을 픽셀로 표현합니다. 그 뒤 레이어가 나뉘어 있다면 합성 과정에서 화면에 배치될 수 있습니다. 변경 종류에 따라 필요한 작업의 범위가 달라집니다.

### DOM 트리와 렌더 트리는 일대일로 대응하는가?

아닙니다. `display: none`처럼 레이아웃 대상에서 제외되는 DOM 노드가 있고 생성 콘텐츠 등 DOM과 다른 렌더 객체도 있을 수 있습니다. 두 구조는 목적과 포함 대상이 달라 일대일 대응하지 않습니다.
