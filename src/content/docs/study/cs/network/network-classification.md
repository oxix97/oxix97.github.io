유니캐스트와 LAN은 모두 네트워크를 설명하는 말이지만 같은 질문에 답하지 않는다. 전달 대상과 연결 범위를 분리하면 HTTP, 멀티캐스트, 리전 간 통신을 한 축에서 잘못 비교하는 일을 피할 수 있다.

## 핵심 요약

- 유니캐스트·멀티캐스트·브로드캐스트는 **누구에게 전달하는가**를 구분한다.
- LAN·MAN·WAN은 **어느 정도 범위를 연결하는가**를 구분한다.
- 브로드캐스트는 링크 계층과 IPv4에서 쓰이지만 IPv6에는 브로드캐스트 주소가 없다. IPv6는 해당 기능을 멀티캐스트로 대체한다.
- 이 두 분류는 성능이나 보안 등급이 아니다. 실제 경로와 프로토콜을 따로 확인해야 한다.

## 전달 대상에 따른 분류

유니캐스트는 하나의 목적지 주소에 해당하는 인터페이스로 전달한다. 멀티캐스트는 그룹 주소에 가입한 수신 인터페이스 집합으로 전달한다. 브로드캐스트는 정해진 로컬 범위의 모든 수신자를 대상으로 한다. 멀티캐스트와 브로드캐스트 모두 여러 노드가 받을 수 있지만 전자는 그룹 구성원을, 후자는 브로드캐스트 범위를 대상으로 한다.

IP 계층과 링크 계층의 전달 방식도 구분해야 한다. Ethernet의 ARP Request는 링크 계층 브로드캐스트이고, IPv4의 `255.255.255.255`는 로컬 네트워크 밖으로 전달하지 않는 제한 브로드캐스트다. IPv6 주소 체계에는 브로드캐스트가 없으며, 이웃 탐색 같은 기능은 멀티캐스트를 사용한다.

**브로드캐스트를 모든 IP 버전과 라우터 경로에 공통인 전달 방식으로 일반화하면 안 된다.**

## 유니캐스트·멀티캐스트·브로드캐스트 비교

| 방식 | 전달 대상 | 대표적인 상황 | 설계 시 확인할 점 |
| --- | --- | --- | --- |
| 유니캐스트 | 하나의 목적지 인터페이스 | 클라이언트와 서버 사이의 일반적인 HTTP 연결 | 목적지 선택, 연결 수, 경로와 지연 |
| 멀티캐스트 | 그룹 주소에 가입한 인터페이스 집합 | IP 멀티캐스트로 같은 데이터를 그룹에 배포 | 그룹 가입, 멀티캐스트 라우팅, 네트워크 장비 지원 |
| 브로드캐스트 | 정해진 로컬 범위의 모든 인터페이스 | Ethernet ARP Request, IPv4 DHCP 탐색 | 계층과 범위, 불필요한 수신 처리, 폭주 방지 |

유니캐스트로 같은 데이터를 여러 수신자에게 보내면 수신자별 흐름이 필요하다. IP 멀티캐스트에서는 송신자가 수신자별 복사본을 만들지 않고 그룹 주소로 보내며, 네트워크가 경로가 갈라지는 지점에서 패킷을 복제할 수 있다. 다만 그룹 관리와 멀티캐스트 라우팅이 준비되어야 한다. 브로드캐스트는 범위 안의 모든 노드가 프레임이나 패킷을 받아 판단하므로 도메인이 커질수록 불필요한 처리가 늘 수 있다.

이 세 방식이 모든 주소 유형을 나열하는 것은 아니다. IPv6는 유니캐스트·애니캐스트·멀티캐스트 주소 유형을 정의한다. 애니캐스트는 같은 주소를 여러 인터페이스에 할당하고 라우팅이 그중 하나로 전달한다는 점에서 그룹 전체에 복제하는 멀티캐스트와 다르다.

## 통신 범위에 따른 분류

LAN, MAN, WAN은 패킷의 수신자 수가 아니라 네트워크의 연결 규모를 설명하는 관습적 분류다. LAN은 집, 사무실, 데이터센터처럼 제한된 영역을 연결한다. MAN은 도시권의 여러 네트워크를, WAN은 더 넓은 지역과 서로 떨어진 사이트를 연결하는 맥락에서 쓴다. 각 범주를 나누는 보편적인 거리 경계가 있는 것은 아니다.

실무에서는 거리뿐 아니라 소유·운영 주체, 회선 기술, 라우팅 경계도 함께 본다. 범위가 넓어지면 중간 경로와 운영 주체가 늘 수 있지만 WAN이라고 반드시 느리거나 LAN이라고 항상 빠른 것은 아니다. 실제 성능은 경로, 혼잡, 링크 품질, 종단 처리 시간을 측정해 판단한다.

## LAN·MAN·WAN 비교

| 범위 | 연결하는 대상 | 일반적인 예 | 백엔드 관점의 확인 사항 |
| --- | --- | --- | --- |
| LAN | 집·사무실·데이터센터처럼 가까운 장소의 장비 | 사내 서비스와 데이터베이스가 있는 네트워크 | 스위치, VLAN, 내부 주소 체계, 국지적 장애 범위 |
| MAN | 도시권의 여러 근거리 네트워크 | 서로 다른 지사의 도시권 연결 | 사업자 구간, 회선 이중화, 지점 간 지연시간 |
| WAN | 국가·대륙 등 광역의 네트워크 | 리전 간 서비스 호출과 인터넷 경로 | 인터넷·전용선 경로, RTT, 장애 우회, 데이터 전송 비용 |

LAN 안에서도 IP 주소와 Ethernet MAC 주소는 서로 다른 계층의 식별자다. 원격 목적지로 보낼 때 호스트는 보통 목적지 서버의 MAC 주소가 아니라 다음 홉 라우터의 링크 계층 주소로 프레임을 전달한다. MAN과 WAN에서는 라우팅·사업자 경계·회선 이중화를 더 많이 고려하지만, NAT나 사설 주소 사용 여부가 이 범주를 결정하지는 않는다.

**LAN·MAN·WAN은 성능 등급이 아니라 경로와 운영 경계를 질문하기 위한 분류다.**

## 백엔드 통신은 어떤 방식에 해당하는가

일반적인 REST API와 gRPC 연결은 각 홉에서 유니캐스트 흐름으로 전달된다. DNS, 애니캐스트 주소, 로드밸런서가 진입 지점을 고를 수 있지만 선택된 구간의 패킷이 그룹 전체에 복제되는 것은 아니다. 이 흐름이 한 데이터센터 LAN에 머무르는지, 외부 사업자나 리전 사이 WAN을 지나는지는 별도의 범위 문제다.

Kafka 생산자는 브로커에 레코드를 쓰고, 소비자 그룹 안에서는 파티션을 기준으로 소비자에게 메시지 처리가 분배된다. Kafka 소비자 그룹의 메시지 분배는 네트워크 계층의 IP 멀티캐스트와 같지 않으며, 브로커 기반 애플리케이션 계층의 저장·구독·파티션 할당 동작이다. 같은 토픽을 여러 소비자 그룹이 구독할 수 있다는 사실도 IP 멀티캐스트 패킷이 네트워크에서 특정 그룹으로 전달되는 방식과는 구분해서 설계해야 한다.

## 장점과 한계

전달 대상과 통신 범위를 분리하면 REST API, IP 멀티캐스트, 리전 간 호출에 서로 다른 질문을 할 수 있다. 대상 분류는 패킷 복제와 수신 범위를, 연결 규모 분류는 경로·운영 주체·장애 경계를 살피게 한다.

하지만 이 분류만으로 성능이나 보안 수준을 확정할 수는 없다. 멀티캐스트 지원, 브로드캐스트 도메인, 애니캐스트 라우팅, 암호화와 접근 제어는 별도 설계 대상이다. 계층을 명시하지 않으면 같은 브로드캐스트라는 말도 링크 계층과 IPv4에서 다른 범위를 가리킬 수 있다.

## 기술면접 질문

### 유니캐스트와 브로드캐스트의 차이

유니캐스트는 하나의 목적지 인터페이스로 전달하고, 브로드캐스트는 정해진 로컬 범위의 모든 인터페이스로 전달합니다. 일반적인 HTTP 연결은 각 홉에서 유니캐스트 흐름을 사용합니다. 브로드캐스트는 Ethernet과 IPv4에서 쓰이지만 IPv6에는 브로드캐스트 주소가 없고 멀티캐스트가 그 기능을 대신합니다.

### 멀티캐스트와 Kafka 소비자 그룹의 차이

IP 멀티캐스트는 그룹 주소에 가입한 인터페이스들로 패킷을 전달하는 네트워크 계층 방식입니다. Kafka 소비자 그룹은 브로커에 저장된 레코드를 파티션 할당에 따라 소비자들이 나누어 처리하는 애플리케이션 계층 동작입니다. Kafka의 저장·재처리·오프셋과 파티션 배분을 IP 멀티캐스트의 패킷 복제로 설명하면 안 됩니다.

### LAN·MAN·WAN이 구분하는 기준

LAN·MAN·WAN은 수신자 수가 아니라 네트워크의 지리적·운영적 연결 규모를 구분합니다. 범주 사이에 보편적인 거리 경계가 있는 것은 아니며 소유 주체와 회선·라우팅 경계도 함께 봅니다. WAN이라고 항상 느리거나 LAN이라고 항상 빠른 것은 아니므로 실제 지연과 가용성은 경로별로 측정해야 합니다.

## 복습 체크리스트

- [ ] 유니캐스트·멀티캐스트·브로드캐스트를 계층과 전달 대상 기준으로 비교할 수 있다.
- [ ] 유니캐스트·멀티캐스트·브로드캐스트를 전달 대상이라는 하나의 기준으로 비교할 수 있다.
- [ ] IPv6에 브로드캐스트 주소가 없고 멀티캐스트가 그 기능을 대신함을 설명할 수 있다.
- [ ] 애니캐스트가 그룹 전체로 복제하는 멀티캐스트와 다름을 설명할 수 있다.
- [ ] LAN·MAN·WAN을 통신 범위라는 독립적인 기준으로 설명할 수 있다.
- [ ] 로드밸런서를 거치는 API 흐름도 구간별 유니캐스트로 설명할 수 있다.
- [ ] REST API와 gRPC의 일반적인 요청·응답을 유니캐스트 관점으로 설명할 수 있다.
- [ ] Kafka 소비자 그룹 분배와 네트워크 계층의 IP 멀티캐스트를 구분할 수 있다.
