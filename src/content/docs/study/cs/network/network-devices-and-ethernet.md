Spring Boot 서버가 실행 중이어도 사용자의 요청이 서버에 도달하지 못할 수 있다. 요청이 지나가는 장치마다 어떤 정보를 보고 전달을 결정하는지 알면 문제를 조사할 위치를 나눌 수 있다.

## 핵심 요약

- L2 스위치는 MAC 주소를 보고 현재 링크의 프레임을 전달하고, 라우터는 IP 목적지로 다음 경로를 고른다.
- 원격 서버로 가는 첫 프레임의 목적지는 보통 기본 게이트웨이의 MAC 주소다. IP 목적지는 원격 서버를 가리킨다.
- L4 로드밸런서는 주로 IP 주소와 포트 등으로 연결이나 흐름을 분산하고, L7 로드밸런서는 HTTP 경로 같은 요청 정보도 활용한다.
- 헬스 체크는 설정된 검사에 대한 응답을 확인한다. 서비스의 모든 기능이 정상이라는 보장은 아니다.

## 요청 경로와 계층별 장치

네트워크 장치는 모두 같은 정보를 보고 동작하지 않는다. 아래 표는 OSI 모델을 기준으로 주로 사용하는 정보와 데이터 단위(PDU)를 정리한 것이다.

| OSI 계층 | 대표 장치·기능 | 전달에 활용하는 정보 | 대표 PDU |
| --- | --- | --- | --- |
| L7 애플리케이션 | L7 로드밸런서 | HTTP 호스트·경로·헤더 등 | 메시지 |
| L4 전송 | L4 로드밸런서 | IP 주소·포트·전송 프로토콜 | TCP 세그먼트 / UDP 데이터그램 |
| L3 네트워크 | 라우터·L3 스위치 | 목적지 IP 주소 | 패킷 |
| L2 데이터 링크 | L2 스위치·브리지 | MAC 주소 | 프레임 |
| L1 물리 | 리피터·허브 | 물리적 신호 | 비트 |

TCP/IP 모델의 애플리케이션 계층은 OSI의 상위 세 계층에, 네트워크 접근 계층은 데이터 링크·물리 계층에 대략 대응한다. 두 모델은 정확히 일대일로 대응하는 구현 명세가 아니다. [TCP/IP 계층과 캡슐화](/study/network/tcp-ip-layers-and-encapsulation/)에서 이 관계와 PDU를 자세히 다뤘다.

**계층은 장치의 주된 판단 기준을 설명하는 도구다.** 하나의 장비가 여러 계층의 기능을 제공할 수 있고, 상위 계층 기능이 하위 계층의 모든 역할을 대체하는 것은 아니다.

## 같은 LAN과 외부 네트워크의 다음 홉

아래 화살표는 데이터의 전달 방향이다. 같은 LAN의 서버로 보낼 때와 외부 서버로 보낼 때 첫 프레임을 받는 대상을 비교한다.

```text
같은 LAN:   클라이언트 → L2 스위치 → 서버
외부 네트워크: 클라이언트 → L2 스위치 → 기본 게이트웨이/라우터 → 다음 네트워크 → 서버
```

같은 서브넷에 직접 전달하는 경우 호스트는 서버의 MAC 주소를 알아내 프레임을 보낸다. 외부 서버에 기본 경로로 접근한다면 게이트웨이를 다음 홉으로 고르고, 게이트웨이의 MAC 주소로 프레임을 보낸다. IPv4에서 다음 홉의 MAC 주소를 찾는 과정은 [ARP 글](/study/network/ip-mac-arp-rarp/)에서 확인할 수 있다.

**첫 프레임의 목적지 MAC과 IP 패킷의 최종 목적지는 서로 다른 대상일 수 있다.** 단순 라우팅에서 목적지 IP는 원격 서버를 가리키지만, 각 라우터는 다음 링크에 맞는 프레임을 새로 만든다. NAT가 있다면 IP 주소도 바뀔 수 있다.

## L2 스위치는 MAC 주소를 어떻게 학습하는가

같은 LAN의 PC A가 PC B에 프레임을 보낸다고 하자. 스위치는 프레임이 들어온 포트와 **출발지 MAC 주소**를 연결해 MAC 주소 테이블에 학습한다. 이후 목적지 MAC이 테이블에 있으면 해당 포트로 전달한다.

목적지 MAC을 아직 모르면 일반적으로 같은 VLAN의 다른 전달 가능 포트에 프레임을 플러딩한다. B의 응답이 들어오면 B의 출발지 MAC과 포트도 학습해 이후 전달에 사용할 수 있다. 학습한 항목은 시간이 지나면 만료될 수 있고, VLAN이나 포트 설정에 따라 전달 범위가 달라진다.

브리지는 링크 계층에서 네트워크 구간을 연결하고 프레임을 전달하는 장치다. L2 스위치는 여러 포트를 가진 브리지로 이해할 수 있다. 둘 다 IP 경로 대신 링크 계층의 주소를 기준으로 프레임을 다룬다.

## 라우터와 L3 스위치는 다음 경로를 어떻게 고르는가

라우터는 서로 다른 IP 네트워크를 연결한다. 패킷의 목적지 IP를 라우팅 테이블과 비교해 출력 인터페이스와 필요한 다음 홉을 고른다. 다음 홉은 목적지로 가는 경로에서 바로 이어지는 라우터나 직접 연결된 목적지다.

테이블에는 목적지 프리픽스, 다음 홉 또는 출력 인터페이스가 들어갈 수 있다. 일치하는 경로가 여러 개라면 일반적인 IP 전달에서는 가장 구체적인 프리픽스를 먼저 적용한다. 실제 경로 구성에는 라우팅 프로토콜과 정책도 영향을 준다. **항상 물리적으로 가장 짧거나 빠른 경로를 찾는다는 뜻은 아니다.** 자세한 선택 과정은 [라우팅과 라우팅 테이블](/study/network/routing-and-routing-table/)에서 다룬다.

L3 스위치는 L2 스위칭과 IP 라우팅 기능을 함께 제공할 수 있다. 예를 들어 서로 다른 VLAN 사이에서 IP 패킷을 전달한다. L2 스위칭은 프레임의 MAC 주소를, L3 전달은 IP 목적지와 경로를 기준으로 한다.

## 이더넷 프레임에서 확인할 부분

| 부분 | 역할 | 복습할 질문 |
| --- | --- | --- |
| 목적지·출발지 MAC | 현재 링크의 전달 상대를 나타낸다 | 외부 서버로 갈 때 첫 프레임의 목적지 MAC은 누구인가? |
| EtherType 또는 길이 필드 | 뒤에 실린 데이터의 종류 또는 길이 해석에 쓰인다 | IPv4와 IPv6를 어떻게 구분하는가? |
| 페이로드 | IP 패킷 등 상위 계층 데이터를 싣는다 | MTU가 제한하는 범위는 어디인가? |
| FCS | 프레임 오류를 검출한다 | 오류 검출이 종단 간 전달 보장과 같은가? |

이 표는 일반적인 Ethernet II 프레임을 읽기 위한 개요다. VLAN 태그와 매체별 헤더 등 실제 형식은 달라질 수 있다. FCS는 손상 검출에 쓰이며, 그 자체가 TCP 같은 종단 간 재전송을 제공하지는 않는다. [MTU 글](/study/network/mtu-mss-pmtud-nagle/)의 1500바이트 예시는 이더넷 헤더 전체가 아니라 IP 패킷에 허용된 크기를 가정한다.

## L4와 L7 로드밸런서는 무엇을 보고 분산하는가

로드밸런서는 여러 대상 서버로 트래픽을 나눠 한 서버에 요청이 집중되는 상황을 줄인다. 대상이 여러 대면 일부 장애에 대응하기도 쉽지만, 로드밸런서만으로 서비스 전체의 고가용성이나 개별 서버의 처리 성능이 보장되지는 않는다.

| 비교 기준 | L4 로드밸런서 | L7 로드밸런서 |
| --- | --- | --- |
| 주로 활용하는 정보 | IP 주소, 포트, TCP·UDP 등 전송 정보 | HTTP 호스트, 경로, 헤더 등 요청 정보 |
| 전달 결정 예시 | TCP 연결이나 UDP 흐름을 대상에 분산 | HTTP 경로에 따라 대상 그룹을 선택 |
| AWS 예시 | Network Load Balancer(NLB) | Application Load Balancer(ALB) |

L4는 HTTP 경로를 해석하지 않고도 TCP 연결이나 UDP 흐름을 분산하는 상황에 활용할 수 있다. NLB는 리스너에 설정된 프로토콜과 포트로 트래픽을 받고 흐름 정보를 사용해 대상을 선택한다. UDP 자체는 비연결형이지만 NLB는 UDP 흐름의 상태를 관리한다. TLS 리스너 등 실제 처리 방식은 설정에 따라 달라진다.

L7은 HTTP 요청의 내용을 기준으로 서비스별 대상을 구분할 때 유용하다. **경로 기반 라우팅은 대상 그룹을 고르는 일이고, 부하 분산은 선택된 그룹의 대상들에 트래픽을 나누는 일이다.** L4가 항상 빠르거나 L7이 항상 느리다고 단정할 수는 없다. 실제 성능은 제품, 프로토콜 처리, 설정과 부하 조건에서 측정해야 한다.

## 백엔드 요청과 ALB 헬스 체크

다음은 실제 운영 경험이 아닌 예시 아키텍처다. 화살표는 요청 전달 방향이며 각 대상 그룹에 Spring Boot 서버 두 대가 등록되어 있다고 가정한다.

```text
Client → Internet → ALB
                    ├─ /api/orders   → 주문 대상 그룹 → 주문 서버 A 또는 B
                    └─ /api/payments → 결제 대상 그룹 → 결제 서버 A 또는 B
```

ALB는 리스너 규칙의 경로 조건을 확인해 요청을 대상 그룹으로 보낸다. 선택된 그룹에서는 설정된 분산 방식에 따라 대상을 고른다. 예를 들어 `/api/orders`는 주문 그룹으로, `/api/payments`는 결제 그룹으로 보낼 수 있다. HTTPS를 ALB에서 종료하도록 설정하면 ALB가 요청을 해석한 뒤 대상과 별도의 연결을 맺는다.

ALB는 대상 그룹마다 설정한 경로와 포트로 주기적으로 헬스 체크 요청을 보낸다. 응답 코드, 시간 제한과 연속 성공·실패 횟수 등의 조건에 따라 대상의 상태를 판단한다. 서버 하나가 비정상으로 판정되고 정상 대상이 남아 있다면 일반적으로 정상 대상으로 요청을 보낸다. 다만 대상 그룹의 모든 등록 대상이 비정상인 경우 등에는 ALB가 비정상 대상에도 요청을 보내는 fail-open 동작이 가능하다.

**헬스 체크가 통과해도 검사하지 않은 주문 처리나 데이터베이스 연동까지 정상이라는 뜻은 아니다.** 접속 장애를 조사할 때는 먼저 ALB의 대상 상태와 실패 원인, 보안 그룹과 포트 접근성을 확인한다. 요청이 애플리케이션에 도달했다면 서버 로그와 응답, 의존 서비스 상태를 함께 살핀다. 단일 지표만으로 네트워크 장애와 애플리케이션 장애를 확정하지 않는다.

## 물리 신호와 NIC·리피터·AP

물리 계층은 비트를 전기·광·무선 신호로 표현해 매체를 통해 전달한다. 리피터는 신호를 재생하거나 중계해 도달 범위를 늘리는 데 쓰이고, 허브는 여러 포트로 신호를 중계하는 다중 포트 리피터다.

NIC는 호스트를 네트워크에 연결하는 인터페이스다. 매체에 신호를 송수신하는 물리 계층뿐 아니라 이더넷 프레임과 MAC 주소를 처리하는 데이터 링크 계층에도 관여한다. AP는 무선 단말이 네트워크에 연결하도록 하고 보통 무선과 유선 링크 사이에서 프레임을 중계한다. AP 역시 물리 계층에만 속하지 않는다.

가정용 공유기는 제품에 따라 라우터, 스위치, 무선 AP 등의 기능을 함께 제공한다. 반면 AP라는 이름은 주로 무선 접속 기능을 가리킨다. 유선과 무선에서 매체를 공유하는 방식은 [유선 LAN과 Wi-Fi](/study/network/wired-lan-and-wifi/)에서 이어서 살펴본다.

## 장점과 한계

장치별 판단 기준을 알면 스위치의 프레임 전달, 라우팅, 로드밸런서의 대상 선택을 서로 다른 위치에서 조사할 수 있다. IP와 MAC의 범위를 구분하면 패킷 캡처를 읽는 데도 도움이 된다.

실제 경로는 VLAN, NAT, 터널, 방화벽, 프록시 때문에 예시보다 복잡하다. 관리형 클라우드 서비스의 내부 장비 구성을 위 그림처럼 단정할 수도 없다. 장치 이름과 계층만으로 장애를 확정하지 말고 실제 설정과 관측 결과를 확인해야 한다.

## 기술면접 질문

### L4와 L7 로드밸런서의 차이는 무엇인가?

L4 로드밸런서는 주로 IP 주소와 포트 등 전송 정보를 사용해 연결이나 흐름을 분산합니다. L7 로드밸런서는 HTTP 경로나 호스트 같은 애플리케이션 정보도 확인해 대상을 선택할 수 있습니다. 예를 들어 L7은 주문과 결제 요청을 다른 대상 그룹으로 보낼 수 있지만 실제 성능과 연결 처리 방식은 제품과 설정에 따라 달라집니다.

### L2 스위치와 L3 스위치의 차이는 무엇인가?

L2 스위치는 MAC 주소 테이블을 이용해 같은 링크 영역의 프레임을 전달합니다. L3 스위치는 여기에 더해 IP 목적지와 라우팅 정보를 바탕으로 네트워크 사이의 패킷을 전달할 수 있습니다. 실제 장비는 두 기능을 함께 제공할 수 있으므로 제공 기능과 구성을 확인해야 합니다.

### 외부 서버로 보내는 요청에서 스위치와 라우터는 각각 무엇을 하는가?

호스트는 라우팅 결과에 따라 기본 게이트웨이를 다음 홉으로 고르고, 그 MAC 주소를 목적지로 한 프레임을 보냅니다. L2 스위치는 MAC 주소를 이용해 프레임을 게이트웨이 쪽으로 전달합니다. 라우터는 IP 목적지와 라우팅 정보를 보고 다음 경로를 골라 새 프레임을 만들며, NAT가 없다면 목적지 IP는 원격 서버를 가리키지만 MAC 주소는 홉에 따라 달라질 수 있습니다.

- [ ] 같은 LAN과 외부 네트워크에서 다음 홉을 각각 설명할 수 있다.
- [ ] IP 목적지와 첫 프레임의 MAC 목적지가 다른 이유를 설명할 수 있다.
- [ ] 스위치의 MAC 주소 학습과 목적지를 모를 때의 전달을 설명할 수 있다.
- [ ] 라우터와 L3 스위치가 IP 목적지와 경로를 사용하는 방식을 설명할 수 있다.
- [ ] 이더넷 프레임의 주요 부분과 FCS의 한계를 설명할 수 있다.
- [ ] L4·L7의 판단 기준과 경로 기반 라우팅·부하 분산을 구분할 수 있다.
- [ ] 헬스 체크의 의미와 ALB의 fail-open 예외를 설명할 수 있다.
- [ ] NIC와 AP가 물리 계층에만 한정되지 않는 이유를 설명할 수 있다.
