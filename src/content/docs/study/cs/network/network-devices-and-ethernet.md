IP 주소를 알고 있어도 패킷이 곧바로 목적지 서버에 전달되지는 않는다. 호스트는 다음에 전달할 대상을 고르고, 같은 링크에서 그 대상의 주소로 프레임을 보낸다. [라우팅](/study/network/routing-and-routing-table/)과 [ARP](/study/network/ip-mac-arp-rarp/)에서 배운 결정을 실제 장치 경로에 놓아 보자.

## 핵심 요약

- 호스트는 라우팅 결과에 따라 같은 링크의 목적지 또는 기본 게이트웨이를 다음 홉으로 정한다.
- 이더넷 프레임의 목적지 MAC 주소는 현재 링크의 수신 대상이고, IP 패킷의 목적지 주소는 최종 목적지를 가리킨다.
- 스위치는 링크 계층에서 프레임을 전달하고, 라우터는 IP 패킷의 다음 경로를 결정한다.
- L4·L7 로드밸런서의 구분은 관찰·처리하는 정보에 관한 실무 용어다. 제품의 실제 동작은 구성에 따라 달라진다.

## 같은 LAN과 외부 네트워크의 다음 홉

같은 서브넷의 서버로 보낼 때 호스트는 그 서버의 MAC 주소를 알아내어 프레임을 보낸다. 외부 네트워크의 서버라면 기본 게이트웨이를 다음 홉으로 고르고, 게이트웨이의 MAC 주소로 프레임을 보낸다. 이때 IP 패킷의 목적지는 외부 서버 주소를 유지한다. NAT 같은 기능이 경로에 있으면 주소가 변할 수 있지만, 단순 라우팅과는 별도의 동작이다.

```text
같은 LAN: 호스트 → 스위치 → 대상 호스트
다른 LAN: 호스트 → 스위치 → 기본 게이트웨이/라우터 → 다음 네트워크 → 대상
```

스위치는 학습한 MAC 주소와 포트를 바탕으로 프레임을 전달한다. 라우터는 IP 목적지와 라우팅 테이블을 보고 다음 홉을 고른다. 각 라우팅 홉에서 링크 계층 프레임은 새 링크에 맞게 다시 만들어질 수 있다. 따라서 **최종 목적지 IP와 매 링크의 목적지 MAC을 같은 주소로 외우면 안 된다.**

## 이더넷 프레임에서 확인할 부분

| 부분 | 역할 | 복습할 질문 |
| --- | --- | --- |
| 목적지·출발지 MAC | 현재 링크의 전달 상대를 나타낸다 | 외부 서버로 갈 때 첫 프레임의 목적지 MAC은 누구인가? |
| EtherType 또는 길이 필드 | 뒤에 실린 데이터의 종류 또는 길이 해석에 쓰인다 | IPv4와 IPv6를 어떻게 구분하는가? |
| 페이로드 | IP 패킷 등 상위 계층 데이터를 싣는다 | MTU가 제한하는 범위는 어디인가? |
| FCS | 프레임 오류를 검출한다 | 오류 검출이 종단 간 전달 보장과 같은가? |

이 표는 일반적인 Ethernet II 프레임을 읽기 위한 개요다. VLAN 태그와 매체별 헤더 등 실제 형식은 달라질 수 있다. FCS는 손상 검출에 쓰이며, 그 자체가 TCP 같은 종단 간 재전송을 제공하지는 않는다. [MTU 글](/study/network/mtu-mss-pmtud-nagle/)의 1500바이트 예시는 이더넷 헤더 전체가 아니라 IP 패킷에 허용된 크기를 가정한다.

## 장치 이름을 계층과 연결하기

| 장치·기능 | 주로 보는 정보 | 대표적인 역할 |
| --- | --- | --- |
| 리피터·허브 | 물리 신호 | 신호를 전달한다. 현대 스위치의 주소 학습과는 다르다. |
| L2 스위치·브리지 | MAC 주소·프레임 | 같은 링크 영역 안에서 전달 포트를 고른다. |
| 라우터·L3 스위치 | IP 주소·패킷 | 네트워크 사이의 다음 경로를 고른다. |
| L4 로드밸런서 | 주소·포트와 연결 정보 | 여러 서버로 연결을 분산한다. |
| L7 로드밸런서·프록시 | HTTP 호스트·경로 등 애플리케이션 정보 | 요청 내용에 따라 전달 대상을 고를 수 있다. |

실제 장비는 여러 계층의 기능을 한 제품에 담기도 한다. 로드밸런서가 TLS를 종료하거나 프록시가 새 연결을 만드는 경우도 있다. 따라서 이름보다 **어느 필드를 보고 어떤 결정을 내리는지**를 확인한다.

## 장점과 한계

장치별 판단 기준을 알면 ARP 실패, 스위치 전달 문제, 라우팅 오류, 로드밸런서 대상 서버 오류를 서로 다른 위치에서 조사할 수 있다. IP와 MAC의 범위를 분리하면 패킷 캡처도 읽기 쉬워진다.

다만 현실 경로는 터널, VLAN, NAT, 프록시 때문에 그림보다 복잡하다. 장치가 반드시 한 계층에서만 동작한다고 가정하지 말고 실제 구성과 캡처로 확인해야 한다.

## 기술면접 질문

### 외부 서버에 보낼 때 첫 이더넷 프레임의 목적지 MAC은 누구 것인가?

일반적인 기본 게이트웨이 경로라면 게이트웨이 인터페이스의 MAC 주소입니다. IP 패킷의 목적지 주소는 외부 서버를 가리킵니다. 첫 링크의 프레임은 바로 다음 홉에 전달해야 하므로 두 주소의 대상이 다릅니다.

### 스위치와 라우터의 전달 기준은 무엇이 다른가?

L2 스위치는 주로 프레임의 MAC 주소와 학습한 포트 정보를 사용합니다. 라우터는 IP 목적지와 라우팅 테이블로 다음 경로를 선택합니다. 실제 장비는 기능을 함께 제공할 수 있습니다.

### FCS가 있으면 TCP 재전송이 필요 없는가?

그렇지 않습니다. FCS는 현재 링크의 프레임 손상을 검출하는 장치입니다. 여러 홉을 지나는 동안의 손실과 종단 간 순서 보장은 별도의 문제이므로 TCP의 확인과 재전송이 필요할 수 있습니다.
