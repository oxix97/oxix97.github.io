IPv4의 점으로 구분한 십진수와 IPv6의 콜론으로 구분한 16진수는 모양부터 다르다. 하지만 두 주소 모두 비트열을 사람이 읽기 편한 형태로 적은 것이다. 자릿값부터 확인하면 서브넷 마스크와 프리픽스 길이도 같은 기준으로 읽을 수 있다.

## 핵심 요약

- 이진수의 각 자리는 오른쪽부터 `2^0`, `2^1`, `2^2`의 자릿값을 갖는다.
- IPv4 주소는 32비트를 8비트 옥텟 네 개로 나누고 각 옥텟을 십진수로 쓴다.
- IPv6 주소는 128비트를 16비트 그룹 여덟 개로 나누고 각 그룹을 16진수로 쓴다.
- IPv6의 `::`는 연속된 0 그룹을 한 번만 압축할 수 있다. 한 그룹 안의 앞쪽 0도 생략할 수 있다.
- IPv6는 더 큰 주소 공간과 단순한 기본 헤더를 제공하지만, 사용만으로 성능 향상이나 암호화가 보장되지는 않는다.

## 이진수의 자릿값으로 IP 주소 읽기

십진수는 각 자리에 10의 거듭제곱을 곱한다. `123`은 `1 × 10^2 + 2 × 10^1 + 3 × 10^0`이다. 이진수도 계산 방법은 같고 밑만 2로 바뀐다. 각 자리는 0 또는 1이며 오른쪽부터 2의 거듭제곱 값을 갖는다.

강의의 예시인 십진수 181을 8비트 이진수로 바꾸면 다음과 같다.

```text
181 = 128 + 32 + 16 + 4 + 1
    = 2^7 + 2^5 + 2^4 + 2^2 + 2^0
    = 10110101₂
```

반대로 `11001010₂`는 값이 1인 자리의 자릿값을 더한다.

```text
11001010₂ = 128 + 64 + 8 + 2
           = 202
```

8비트로 만들 수 있는 조합은 `2^8`개다. 최솟값은 `00000000₂`인 0이고 최댓값은 `11111111₂`인 255다. 그래서 IPv4의 각 옥텟은 0부터 255 사이의 십진수로 나타난다.

## IPv4는 32비트를 네 옥텟으로 나눈다

IPv4 주소는 32비트다. 이론적으로 `2^32`, 즉 4,294,967,296개의 비트 조합을 표현한다. 다만 네트워크 주소, 브로드캐스트 주소, 사설 주소, 루프백과 여러 특수 목적 범위가 있으므로 이 수가 모두 전역 호스트에 배정되는 것은 아니다.

IPv4 텍스트 표기는 32비트를 8비트씩 네 옥텟으로 나눈다. 각 옥텟은 십진수로 바꾸고 점으로 구분한다.

```text
10101100.00010000.11111110.00000001
   172  .    16  .   254  .    1

IPv4 주소: 172.16.254.1
```

주소만 보고 어느 비트까지가 네트워크 부분인지는 알 수 없다. `172.16.254.1/24`처럼 프리픽스 길이나 서브넷 마스크를 함께 알아야 한다. 이 기준은 다음 글에서 CIDR과 서브네팅을 계산할 때 사용한다.

**점 앞뒤의 숫자는 네 개의 독립된 번호가 아니라 하나의 32비트 주소를 8비트씩 끊어 표시한 결과다.**

## IPv6는 128비트를 16진수로 표현한다

IPv6 주소는 128비트다. 가능한 비트 조합은 `2^128`개이며 약 `3.4 × 10^38`개다. 128개의 0과 1을 그대로 쓰기 어려우므로 16비트씩 여덟 그룹으로 나누고 16진수로 적는다. 각 그룹은 hextet이라고도 부르며 콜론으로 구분한다.

```text
2001:0db8:0000:0000:0000:0000:0000:0001
```

한 그룹의 앞쪽 0은 생략할 수 있다. 위 주소의 `0db8`은 `db8`, `0001`은 `1`로 쓸 수 있다. 연속된 0 그룹은 `::`로 한 번 압축할 수 있다.

```text
2001:0db8:0000:0000:0000:0000:0000:0001
2001:db8:0:0:0:0:0:1
2001:db8::1
```

`::`를 한 주소에서 두 번 쓰면 각각 몇 개의 0 그룹을 나타내는지 결정할 수 없다. 그래서 한 번만 사용할 수 있다. IPv6의 루프백 주소 `0:0:0:0:0:0:0:1`을 `::1`로 쓰는 것도 같은 규칙이다.

## IPv4와 IPv6의 프로토콜 차이

주소 길이 외에도 기본 헤더와 패킷 처리 방식이 달라졌다. 다음 표에서는 프로토콜 자체의 차이를 비교한다. 실제 통신 성능은 경로, 장비, 운영체제와 전환 방식의 영향을 함께 받는다.

| 비교 기준 | IPv4 | IPv6 |
| --- | --- | --- |
| 주소 길이 | 32비트 | 128비트 |
| 대표 표기 | 네 개의 십진수 옥텟 | 여덟 개의 16진수 16비트 그룹 |
| 기본 헤더 길이 | 옵션이 없으면 20바이트, 최대 60바이트 | 40바이트로 고정되며 확장 헤더가 뒤따를 수 있다 |
| 헤더 체크섬 | IPv4 헤더에 존재한다 | 기본 헤더에 존재하지 않는다 |
| 경로 중 단편화 | DF가 없고 조건이 맞으면 라우터도 수행할 수 있다 | 라우터는 수행하지 않고 출발지 노드만 Fragment 헤더를 사용한다 |
| 브로드캐스트 | 브로드캐스트 주소를 사용한다 | 브로드캐스트가 없고 멀티캐스트가 그 기능을 대신한다 |
| 이웃 주소 확인 | ARP를 사용한다 | Neighbor Discovery를 사용한다 |
| 수명 필드 | TTL | Hop Limit |

IPv6가 헤더 체크섬을 없앴다는 말은 오류 검출이 전부 사라졌다는 뜻이 아니다. 링크 계층과 TCP 등 상위 계층에도 오류 검출 기능이 있다. IPv6에서 UDP 체크섬은 기본적으로 0으로 생략할 수 없다는 점도 IPv4와 다르다.

IPv6 라우터는 경로 MTU보다 큰 패킷을 직접 조각내지 않는다. 출발지 노드가 Path MTU Discovery 결과에 맞춰 크기를 조절하거나 Fragment 헤더를 사용한다. 이 차이는 라우터의 처리 책임을 줄이지만, 네트워크 전체가 언제나 IPv4보다 빠르다는 결론으로 바로 이어지지는 않는다.

## IPv6와 IPsec을 구분해야 하는 이유

IPv6와 IPsec은 함께 설계 논의가 진행됐고, IPv6 노드 요구사항은 IPsec 아키텍처 지원을 SHOULD로 권고한다. 그러나 지원 여부와 실제 사용 여부는 다르다. 키 관리와 보안 정책을 구성하지 않은 IPv6 패킷이 자동으로 암호화되지는 않는다. IPsec은 IPv4에서도 사용할 수 있다.

따라서 `IPv6는 IPsec이 내장되어 무조건 안전하다`는 설명은 정확하지 않다. 주소 공간이 넓다는 사실도 접근 제어를 대신하지 않는다. IPv6 환경에서도 방화벽 정책, 보안 업데이트, 주소 설정과 이웃 탐색 보호를 별도로 관리해야 한다.

**IPv6가 제공하는 것은 IPsec을 사용할 수 있는 표준 구조이지 모든 IPv6 트래픽의 자동 암호화가 아니다.**

## 장점과 한계

IPv4는 짧은 주소 표기와 넓은 기존 배포 기반을 갖고 있다. 하지만 32비트 주소 공간만으로는 전 세계 장치에 전역 주소를 직접 제공하기 어렵다. 사설 주소와 NAT, 세밀한 주소 할당으로 부족을 완화하지만 운영 복잡성과 상태 관리 비용이 생긴다.

IPv6는 128비트 주소 공간을 제공하고, 기본 헤더를 고정 길이로 단순화했다. 브로드캐스트 대신 멀티캐스트를 사용하며 라우터가 패킷을 단편화하지 않는다. 반면 IPv4와 IPv6가 공존하는 동안에는 이중 스택, 터널, 변환 기술을 운영해야 한다. 실제 성능과 보안은 주소 버전 하나가 아니라 경로와 구현, 설정을 함께 확인해야 한다.

## 기술면접 질문

### IPv4 주소의 각 숫자가 0부터 255까지인 이유는 무엇인가?

IPv4는 32비트를 8비트 옥텟 네 개로 나누어 표기합니다. 8비트로 만들 수 있는 값은 `00000000₂`부터 `11111111₂`까지이며 십진수로 0부터 255입니다. 네 옥텟을 점으로 연결해 하나의 32비트 주소를 표현합니다.

### IPv6 주소의 0을 생략하는 규칙은 무엇인가?

각 16비트 그룹 앞의 0은 생략할 수 있고, 연속된 하나 이상의 0 그룹은 `::`로 압축할 수 있습니다. 다만 `::`는 한 주소에서 한 번만 사용할 수 있습니다. 두 번 쓰면 각각 몇 개의 0 그룹을 뜻하는지 판단할 수 없기 때문입니다.

### IPv6를 사용하면 자동으로 더 빠르고 안전한가?

자동으로 보장되지는 않습니다. IPv6는 고정 길이 기본 헤더와 큰 주소 공간을 제공하지만 실제 속도는 경로, 장비, 운영체제와 전환 방식에 따라 달라집니다. IPsec 지원도 실제 암호화 정책과 키 구성이 있어야 사용되므로 IPv6라는 이유만으로 모든 통신이 암호화되지는 않습니다.
