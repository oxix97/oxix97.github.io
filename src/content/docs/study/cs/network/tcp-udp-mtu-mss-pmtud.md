TCP와 UDP를 “TCP는 안전하고 UDP는 빠르다”로 외우면 애플리케이션이 실제로 받는 보장을 놓치기 쉽다. 두 프로토콜이 오류를 어떻게 다루는지, 체크섬과 CRC가 어디까지 확인하는지 함께 구분해 보자.

## 핵심 요약

- TCP는 순서가 있는 바이트 스트림과 손실 복구를 제공하고, UDP는 데이터그램 경계를 보존하지만 전달·순서를 보장하지 않는다.
- TCP와 UDP 체크섬은 전송 중 손상 검출을 돕는다. 검출만으로 데이터를 복구하지는 않는다.
- Ethernet FCS의 CRC는 링크 프레임 손상을 검출한다. TCP 체크섬과 보호 범위가 다르다.
- 재전송은 TCP의 별도 동작이며, ACK는 상대 애플리케이션의 처리 완료를 뜻하지 않는다.

## TCP와 UDP는 서로 다른 전달 서비스를 제공한다

TCP는 바이트를 순서대로 전달하는 연결 지향 서비스다. 시퀀스 번호와 확인 응답, 재전송으로 손실을 복구한다. 애플리케이션 메시지의 경계는 보존하지 않으므로 요청의 길이나 구분자를 애플리케이션 프로토콜에서 정해야 한다.

UDP는 각 데이터그램의 경계를 보존하고 프로토콜 수준의 연결 설정을 요구하지 않는다. 전달 여부와 순서, 중복 제거를 보장하지 않으므로 필요한 경우 상위 프로토콜이 직접 처리한다.

| 비교 | TCP | UDP |
| --- | --- | --- |
| 전달 단위 | 순서 있는 바이트 스트림 | 독립된 데이터그램 |
| 손실 복구 | ACK·타임아웃 등에 따라 재전송 | 자체 재전송을 제공하지 않음 |
| 메시지 경계 | 제공하지 않음 | 데이터그램 경계를 보존 |
| 체크섬 | 헤더와 데이터의 오류 검출 | 헤더와 데이터의 오류 검출 |

**프로토콜은 막연한 속도 비교보다 순서·손실 복구·메시지 경계를 누가 책임지는지로 고른다.**

TCP의 ACK는 상대 TCP가 해당 바이트를 받았다는 의미다. 애플리케이션이 주문을 처리하거나 데이터베이스에 저장했다는 뜻은 아니다. 업무 처리가 완료됐는지 확인하려면 애플리케이션 수준의 응답이 필요하다.

## 체크섬과 CRC는 손상을 검출한다

체크섬은 데이터에서 계산한 값을 보내고 받는 쪽에서 다시 계산해 비교하는 방식이다. IPv4 헤더와 TCP·UDP에는 1의 보수 합을 이용하는 체크섬이 쓰인다. TCP와 UDP 체크섬은 IP 의사 헤더와 전송 계층 데이터그램도 포함해 잘못된 주소나 프로토콜 연결을 검출하는 데 도움을 준다.

CRC는 비트열을 생성 다항식으로 나눌 때 얻는 나머지를 검증값으로 사용한다. Ethernet 프레임의 FCS는 CRC를 사용해 프레임의 우발적 손상을 검출한다. 손상이 발견된 프레임은 해당 링크에서 폐기될 수 있다.

| 검증값 | 대표 위치 | 확인 범위와 역할 |
| --- | --- | --- |
| IPv4 헤더 체크섬 | IPv4 헤더 | IPv4 헤더 손상 검출 |
| TCP·UDP 체크섬 | 전송 계층 | 의사 헤더와 전송 데이터 손상 검출 |
| Ethernet FCS | Ethernet 프레임 | 한 링크에서 프레임 손상 검출 |

검출 범위가 다르므로 링크를 지나며 프레임은 새로 만들어져도 종단 사이의 TCP 세그먼트 체크섬은 다시 확인할 수 있다. 어떤 체크섬도 손상된 비트를 그 자체로 고치거나 재전송하지 않는다. CRC와 체크섬은 오류 검출 코드이며, 복구는 TCP 재전송이나 상위 계층의 별도 동작이다.

## 장점과 한계

TCP는 순서와 손실 복구를 전송 계층에서 제공해 애플리케이션이 바이트 전달을 매번 구현하지 않게 한다. UDP는 데이터그램 경계를 유지하며 애플리케이션이 필요한 복구와 시간 정책을 선택하게 한다. 체크섬과 CRC는 전송 중 손상을 발견할 수 있다.

오류 검출은 무오류를 증명하지 않으며 오류 정정도 제공하지 않는다. UDP를 선택했다고 반드시 지연이 작아지는 것도 아니다. 필요한 재전송·혼잡 제어를 애플리케이션이 구현하면 그 비용이 생긴다.

## 기술면접 질문

### TCP와 UDP의 가장 큰 차이는 무엇인가?

TCP는 연결 안에서 순서가 있는 바이트 스트림과 손실 복구를 제공합니다. UDP는 데이터그램 경계를 보존하지만 전달과 순서를 보장하지 않습니다. 어떤 보장이 필요한지에 따라 선택하며 TCP의 ACK도 업무 처리 완료를 뜻하지는 않습니다.

### 체크섬과 CRC는 데이터를 복구하는가?

아닙니다. 체크섬과 CRC는 전송 데이터나 프레임의 손상을 검출하는 값입니다. 오류를 발견한 뒤 폐기·재전송·복구를 수행하는 동작은 별도로 정의됩니다.

### Ethernet FCS가 있는데 TCP 체크섬도 필요한 이유는 무엇인가?

Ethernet FCS는 한 링크의 프레임을 검사하고 라우터를 지나 다음 링크로 갈 때 프레임은 새로 만들어집니다. TCP 체크섬은 종단 간 전송 세그먼트를 확인하므로 검증 범위가 다릅니다. 각 계층에서 별도로 검증하는 이유입니다.
