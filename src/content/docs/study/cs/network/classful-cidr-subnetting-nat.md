IPv4 주소 부족은 32비트라는 크기만의 문제가 아니다. 필요한 규모와 맞지 않는 주소 블록을 할당하면 사용하지 못하는 주소가 늘어난다. 클래스풀에서 CIDR로 바뀐 이유와 사설 주소, NAT가 맡은 역할을 함께 보면 어떤 문제를 각각 줄였는지 구분할 수 있다.

## 핵심 요약

- 클래스풀 주소 체계는 A·B·C 클래스마다 네트워크와 호스트의 경계를 고정해 주소 낭비가 컸다.
- CIDR는 `/26`처럼 프리픽스 길이를 직접 표시해 클래스 경계와 무관하게 주소 블록을 할당하고 경로를 집계한다.
- 서브넷 마스크와 IP 주소를 비트 AND하면 네트워크 주소를 구할 수 있다.
- RFC 1918 사설 주소는 여러 조직이 내부에서 재사용할 수 있지만 공용 인터넷에서 직접 라우팅하지 않는다.
- 여러 사설 호스트가 하나의 외부 주소를 공유할 때는 보통 IP 주소와 포트를 함께 변환하는 NAPT를 사용한다.
- NAT는 주소를 변환하는 기능이다. 방화벽 정책이나 종단 보안을 대신하지 않는다.

## 클래스풀 주소 체계가 주소를 낭비한 이유

초기 IPv4 주소 할당은 첫 비트 패턴에 따라 A, B, C 클래스로 나눴다. 클래스마다 네트워크 부분과 호스트 부분의 경계가 정해져 있었다.

| 클래스 | 첫 비트 패턴 | 첫 옥텟 범위 | 기본 경계 | 한 네트워크의 전체 주소 수 |
| --- | --- | --- | --- | --- |
| A | `0` | 0~127 | `/8` | `2^24` |
| B | `10` | 128~191 | `/16` | `2^16` |
| C | `110` | 192~223 | `/24` | `2^8` |

0과 127로 시작하는 범위에는 특수 목적이 있고, 표의 전체 주소 수가 모두 호스트에 배정되는 것도 아니다. 이 표에서 확인할 부분은 클래스별 경계가 `/8`, `/16`, `/24`로 고정된다는 점이다.

예를 들어 5,000개의 주소가 필요한 조직은 256개 단위인 클래스 C 하나로는 부족하다. 다음 크기인 클래스 B를 받으면 65,536개의 주소 공간이 생겨 대부분을 쓰지 못한다. 여러 클래스 C 네트워크를 따로 관리하는 방법도 경로 정보와 운영 부담을 늘린다.

**클래스풀의 문제는 필요한 크기와 실제로 할당할 수 있는 블록 크기 사이의 간격이 너무 컸다는 데 있다.**

## CIDR과 서브네팅은 같은 말이 아니다

CIDR(Classless Inter-Domain Routing)는 클래스 경계를 사용하지 않고 프리픽스 길이로 주소 블록을 표현한다. `192.0.2.0/24`에서 `/24`는 왼쪽 24비트가 네트워크 프리픽스라는 뜻이다. 남은 8비트는 해당 블록 안의 주소를 구분한다.

서브넷 마스크는 프리픽스 비트를 1, 호스트 비트를 0으로 표현한 비트 마스크다. `/24`는 `255.255.255.0`, `/26`은 `255.255.255.192`와 같다. 유효한 IPv4 넷마스크의 1비트는 왼쪽부터 연속된다.

서브네팅은 이미 받은 주소 블록을 더 작은 프리픽스로 나누는 작업이다. 예를 들어 `/24`를 네 개의 `/26`으로 나누는 것이 서브네팅이다. CIDR는 클래스리스 주소 할당과 경로 집계를 포함하는 더 넓은 체계다.

| 용어 | 설명 | 예시 |
| --- | --- | --- |
| 프리픽스 길이 | 왼쪽부터 네트워크 부분으로 사용하는 비트 수 | `/26` |
| 서브넷 마스크 | 프리픽스를 1, 나머지를 0으로 표시한 마스크 | `255.255.255.192` |
| 서브네팅 | 하나의 프리픽스를 더 작은 네트워크로 분할하는 작업 | `/24`를 네 개의 `/26`으로 분할 |
| 경로 집계 | 여러 연속 프리픽스를 더 큰 하나의 경로로 광고하는 작업 | 두 `/25`를 `/24`로 집계 |

CIDR 프리픽스는 앞 글의 라우팅 테이블에서도 사용했다. 여러 경로가 목적지와 일치하면 가장 긴 프리픽스가 더 구체적인 경로로 선택된다.

## `192.168.1.130/26` 계산하기

`/26`은 앞 26비트가 네트워크 부분이고 뒤 6비트가 호스트 부분이라는 뜻이다. 서브넷 마스크의 마지막 옥텟은 `11000000₂`, 즉 192다.

```text
IP 주소 마지막 옥텟     130 = 10000010₂
서브넷 마스크 마지막 옥텟 192 = 11000000₂
                              -------- AND
네트워크 주소 마지막 옥텟 128 = 10000000₂
```

앞의 세 옥텟은 마스크가 모두 1이므로 그대로 남는다. 따라서 네트워크 주소는 `192.168.1.128/26`이다. 호스트 비트 여섯 개를 모두 1로 만들면 마지막 옥텟이 191이므로 브로드캐스트 주소는 `192.168.1.191`이다.

| 항목 | 결과 |
| --- | --- |
| 네트워크 주소 | `192.168.1.128` |
| 첫 번째 일반 호스트 주소 | `192.168.1.129` |
| 마지막 일반 호스트 주소 | `192.168.1.190` |
| 브로드캐스트 주소 | `192.168.1.191` |
| 전체 주소 수 | `2^6 = 64` |
| 일반적인 호스트 할당 수 | `64 - 2 = 62` |

`/26` 블록의 간격은 64다. 같은 `/24` 안에서 네트워크 주소는 `.0`, `.64`, `.128`, `.192`로 시작한다. `192.168.1.130`은 `.128`부터 `.191`까지의 블록에 포함된다.

`2^호스트 비트 수 - 2`는 브로드캐스트를 사용하는 일반 서브넷을 계산할 때 쓰는 규칙이다. 모든 프리픽스에 그대로 적용하면 안 된다. RFC 3021의 IPv4 지점 간 링크에서는 `/31`의 두 주소를 모두 호스트 주소로 사용한다. `/32`는 단일 주소를 가리킨다.

## 사설 주소는 여러 네트워크에서 재사용한다

RFC 1918은 조직 내부에서 사용할 IPv4 사설 주소 범위 세 개를 예약한다.

| 사설 주소 범위 | CIDR 표기 | 주소 범위 |
| --- | --- | --- |
| 10 블록 | `10.0.0.0/8` | `10.0.0.0`~`10.255.255.255` |
| 172.16 블록 | `172.16.0.0/12` | `172.16.0.0`~`172.31.255.255` |
| 192.168 블록 | `192.168.0.0/16` | `192.168.0.0`~`192.168.255.255` |

사설 주소는 한 조직 안에서 유일하게 관리하면 되고, 다른 조직이 같은 주소를 사용할 수 있다. 공용 인터넷 라우터는 이 범위를 전역 목적지로 전달하지 않는다. 외부와 통신하려면 전역 주소를 가진 중간 장치에서 주소를 변환하거나 프록시를 사용해야 한다.

공인 IP라는 표현은 보통 공용 인터넷에서 전역으로 라우팅 가능한 등록 주소를 가리킨다. 하지만 RFC 1918 범위가 아니라고 해서 모두 공인 주소는 아니다. `127.0.0.0/8` 루프백, `169.254.0.0/16` 링크 로컬, 문서 예시용 주소와 멀티캐스트 같은 특수 범위도 따로 있다.

## Basic NAT와 NAPT의 차이

NAT(Network Address Translation)는 패킷이 변환 장치를 지날 때 IP 헤더의 주소를 다른 주소로 바꾼다. Basic NAT는 내부 주소와 외부 주소를 주소 단위로 대응시킨다. NAPT(Network Address Port Translation)는 IP 주소뿐 아니라 TCP·UDP 포트도 함께 바꾼다.

가정용 공유기에서 여러 장치가 하나의 외부 주소를 공유하는 경우는 보통 NAPT다. 다음 표의 외부 주소 `203.0.113.7`은 설명에 사용하는 문서 예시용 주소다.

| 내부 출발지 | 변환 후 출발지 | 외부 목적지 |
| --- | --- | --- |
| `192.168.1.10:51514` | `203.0.113.7:40001` | `198.51.100.20:443` |
| `192.168.1.11:51514` | `203.0.113.7:40002` | `198.51.100.20:443` |

공유기는 두 연결에 서로 다른 외부 포트를 할당하고 변환 상태를 저장한다. 응답이 `203.0.113.7:40001`로 돌아오면 첫 번째 내부 주소로, `40002`로 돌아오면 두 번째 내부 주소로 되돌린다. 하나의 외부 IP 주소를 여러 내부 연결이 동시에 공유할 수 있는 이유다.

외부에서 먼저 시작하는 연결은 대응할 변환 상태가 없으므로 내부 호스트를 자동으로 결정할 수 없다. 정적 NAT나 포트 포워딩처럼 미리 정한 규칙이 필요하다. 프로토콜이 IP 주소나 포트를 페이로드에 포함하거나 종단 간 무결성 검증을 사용하면 별도의 처리 없이 NAT를 통과하기 어려울 수도 있다.

**여러 사설 호스트가 하나의 외부 주소를 공유하는 핵심은 주소 변환만이 아니라 포트와 연결 상태까지 함께 관리하는 NAPT에 있다.**

## 장점과 한계

CIDR는 필요한 규모에 가까운 주소 블록을 할당하고 여러 경로를 집계할 수 있게 한다. 서브네팅은 조직이 받은 주소 공간을 네트워크 경계에 맞게 나누도록 돕는다. 사설 주소와 NAPT를 함께 쓰면 하나의 전역 주소로 여러 내부 호스트의 외부 연결을 처리할 수 있어 IPv4 주소 소비를 줄인다.

NAT 장치에는 연결별 변환 상태가 쌓인다. 사용할 포트가 부족하거나 상태가 사라지면 새 연결과 응답 전달이 실패할 수 있다. 주소와 포트를 바꾸기 때문에 IP 주소가 가진 종단 간 의미도 약해지고, 일부 프로토콜은 NAT traversal이나 ALG 같은 추가 장치가 필요하다.

일반적인 NAPT가 외부에서 시작한 연결을 기본적으로 전달하지 않는 성질은 노출 범위를 줄일 수 있다. 그래도 NAT는 접근 제어 정책을 정의하는 방화벽과 같은 기능이 아니다. 정적 매핑이나 기존 상태를 통한 통신은 허용될 수 있으며, 내부에서 시작한 악성 연결도 NAT만으로 막지 못한다.

## 기술면접 질문

### 클래스풀 주소 체계와 CIDR의 차이는 무엇인가?

클래스풀 주소 체계는 첫 비트 패턴에 따라 네트워크 경계를 `/8`, `/16`, `/24`로 고정합니다. CIDR는 `/20`이나 `/26`처럼 프리픽스 길이를 직접 지정하므로 필요한 크기에 가까운 주소 블록을 할당하고 경로를 집계할 수 있습니다. 현재 라우팅은 클래스가 아니라 프리픽스와 가장 긴 프리픽스 일치를 기준으로 판단합니다.

### `192.168.1.130/26`의 네트워크와 호스트 범위는 어떻게 구하는가?

`/26`의 마스크는 `255.255.255.192`이며 IP 주소와 비트 AND하면 네트워크 주소 `192.168.1.128`이 나옵니다. 호스트 비트 여섯 개를 모두 1로 만든 `192.168.1.191`은 브로드캐스트 주소입니다. 일반 호스트 범위는 `.129`부터 `.190`까지지만 `/31` 지점 간 링크처럼 두 주소를 모두 사용하는 예외도 있습니다.

### NAT와 NAPT는 무엇이 다르며 NAT를 방화벽으로 볼 수 있는가?

Basic NAT는 IP 주소를 다른 IP 주소로 변환하고, NAPT는 IP 주소와 TCP·UDP 포트를 함께 변환해 여러 내부 호스트가 하나의 외부 주소를 공유하게 합니다. 변환 상태가 없는 외부 연결이 바로 들어오기 어렵다는 성질은 있지만 NAT 자체가 방화벽 정책을 대신하지는 않습니다. 접근 제어와 내부에서 시작한 트래픽 검사는 별도로 구성해야 합니다.
