# 라우팅과 라우팅 테이블 학습 글 설계

## 목적

Inflearn `CS 지식의 정석`의 `라우팅 #1. 개념과 라우터`와 `라우팅 #2. 라우팅테이블`을 네트워크 연재 7편으로 정리한다. 강의의 입문 흐름은 유지하되, 경로 선택을 단순히 "가장 빠른 경로"라고 일반화하지 않고 프리픽스, 라우팅 정책, 프로토콜별 비용을 기준으로 설명한다.

개인 학습 경험은 사용하지 않는다. 도입은 라우팅·라우터·라우팅 테이블을 섞어 말하기 쉬우므로 역할과 판단 순서를 구분할 필요가 있다는 중립적인 복습 동기로 작성한다.

## 대상 독자와 완료 기준

대상 독자는 네트워크 기초를 복습하면서 백엔드 운영과 기술면접에 연결하려는 개발자다. 다음을 설명할 수 있으면 글의 목적을 달성한 것으로 본다.

- 라우팅, 라우터, 라우팅 테이블의 관계를 구분한다.
- 목적지 IP가 주어졌을 때 목적지 프리픽스, 다음 홉, 출력 인터페이스를 읽는다.
- 가장 긴 프리픽스 일치와 기본 경로의 역할을 설명한다.
- 메트릭이 낮은 경로가 항상 전역적으로 선택된다고 일반화하지 않는다.
- 운영체제의 라우팅 테이블 출력에서 주요 필드를 찾는다.

## 작성 접근법

강의 순서를 그대로 옮기는 개념 중심형과 면접 답변만 압축하는 요약형 대신, 원리·실무 결합형을 사용한다. `목적지 확인 → 일치하는 경로 탐색 → 가장 구체적인 프리픽스 선택 → 다음 홉과 인터페이스로 전달`이라는 흐름을 중심에 두고 강의 개념, 표, 명령 출력 예시, 기술면접 답변을 연결한다.

## 글 구조

새 글의 파일명은 `src/content/docs/study/cs/network/routing-and-routing-table.md`로 한다. 제목은 `라우터는 다음 경로를 어떻게 고르는가: 라우팅과 라우팅 테이블`로 잡고, `sidebar.order`는 7로 둔다.

본문은 저장소 규칙에 따라 다음 순서로 구성한다.

1. 라우팅과 라우팅 테이블을 구분해야 하는 중립적 복습 동기
2. `핵심 요약`
3. 라우팅·라우터·라우팅 테이블의 관계
4. 목적지 네트워크, 프리픽스, 게이트웨이, 인터페이스, 메트릭
5. 가장 긴 프리픽스 일치와 기본 경로
6. Linux `ip route` 형식의 최소 출력 예시와 읽는 순서
7. `장점과 한계`
8. 기술면접 질문 3개
9. `복습 체크리스트`
10. `참고 자료`
11. 이전 글과 연재 목록 탐색 링크

표는 라우팅 테이블 필드의 의미와 판단 질문을 묶는 데 사용한다. 별도 이미지는 만들지 않는다. 정적 다이어그램보다 한두 줄의 경로 후보와 선택 결과가 가장 긴 프리픽스 일치를 더 직접적으로 보여 주기 때문이다.

## 기술 정확성 보정

- 라우팅은 단순히 물리적으로 가장 빠른 길을 찾는 행위가 아니라, 라우팅 테이블과 정책에 따라 패킷의 다음 전달 경로를 선택하는 과정으로 설명한다.
- 목적지 선택에서는 더 구체적인 프리픽스가 우선되는 가장 긴 프리픽스 일치를 먼저 설명한다.
- 메트릭은 같은 목적지 후보의 선호도를 판단하는 비용 정보로 소개하되, 서로 다른 라우팅 프로토콜과 운영체제의 전체 선택 규칙을 하나의 숫자로 일반화하지 않는다.
- 게이트웨이는 모든 경로에 반드시 존재하는 값이 아니다. 직접 연결된 네트워크는 별도의 다음 홉 라우터 없이 출력 인터페이스로 전달할 수 있음을 밝힌다.
- 홉 수가 적다고 항상 지연시간이 가장 짧지는 않다. 홉 수는 일부 라우팅 프로토콜에서 사용할 수 있는 비용 기준 중 하나로 한정한다.
- 예제 명령은 강의의 Windows `netstat -r`을 언급하되, 저장소 독자의 운영 맥락을 고려해 Linux `ip route`를 본문 예시로 사용한다.

## 기술면접 질문

다음 세 질문을 사용한다.

1. 라우팅과 라우팅 테이블은 무엇이며 어떻게 연결되는가?
2. 여러 경로가 목적지와 일치할 때 어떤 경로가 선택되는가?
3. 게이트웨이, 인터페이스, 메트릭은 각각 무엇을 의미하는가?

답변은 직접 답변, 작동 원리, 적용 범위 또는 예외 순서로 쓰며 `-습니다` 문체를 유지한다.

## 자료와 검증

강의 두 편을 일차 학습 자료로 사용하고, 경로 선택과 CIDR 설명은 표준 문서로 검증한다.

- Inflearn `라우팅 #1. 개념과 라우터 ★★★`
- Inflearn `라우팅 #2. 라우팅테이블 ★★★`
- RFC 1812, `Requirements for IP Version 4 Routers`
- RFC 4632, `Classless Inter-domain Routing (CIDR): The Internet Address Assignment and Aggregation Plan`
- Linux `ip-route(8)` 매뉴얼

완성 후 빌드 또는 저장소의 콘텐츠 검증 명령을 실행한다. 링크, frontmatter, 연재 순서와 이전·다음 탐색 링크도 함께 확인한다.
