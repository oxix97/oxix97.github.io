# 디자인패턴 Study 연재 설계

## 1. 목적

Inflearn의 `CS 지식의 정석 | 디자인패턴 네트워크 운영체제 데이터베이스 자료구조`
강의 중 섹션 2 `디자인패턴`을 개인 언어로 재구성한다. 연재는 다음 두 상황에서
쉽게 다시 사용할 수 있어야 한다.

- 강의 수강 후 핵심 개념을 짧게 복습할 때
- 기술면접 직전에 패턴의 목적, 장단점, 비교 질문을 확인할 때

각 글은 5~10분 안에 읽을 수 있는 분량으로 제한한다. 강의 자막이나 교안을
옮겨 적지 않고, 개념 설명과 예시는 직접 재구성하며 출처 링크를 남긴다.

## 2. 독자와 작성 원칙

주 독자는 디자인패턴을 한 번 학습했지만 패턴별 해결 문제와 차이를 다시
정리하려는 백엔드 개발자다.

- 하나의 글은 하나의 중심 질문에 답한다.
- 정의보다 `어떤 문제를 해결하는가`를 먼저 설명한다.
- Java 또는 Spring 예시는 핵심 구조가 드러나는 최소 크기로 작성한다.
- 장점뿐 아니라 결합도, 상태 관리, 테스트, 동시성 등의 단점을 함께 설명한다.
- 면접 답변은 암기 문장이 아니라 근거와 선택 기준을 포함한다.
- 강의에 없는 세부 내용을 보충할 경우 공식 문서 등 별도 출처를 표시한다.

## 3. 정보 구조

연재는 `Study` 아래 별도 디렉터리로 묶는다.

```text
src/content/docs/study/
├── index.md
└── design-patterns/
    ├── index.md
    ├── introduction.md
    ├── singleton-basics.md
    ├── singleton-implementations.md
    ├── factory-and-iterator.md
    ├── dependency-injection-and-strategy.md
    ├── observer-and-proxy.md
    ├── mvc-mvp-mvvm.md
    └── flux-and-review.md
```

`design-patterns/index.md`는 연재 소개와 권장 학습 순서를 보여주는 허브다.
기존 `study/index.md`에는 이 허브로 가는 링크를 추가한다. 각 글의 앞뒤에는
이전 글, 연재 목록, 다음 글 링크를 배치한다.

## 4. 연재 구성

| 순서 | 글 제목 | 중심 내용 | 주요 면접 포인트 |
| --- | --- | --- | --- |
| 1 | 디자인 패턴이란 무엇인가 | 디자인패턴의 목적, 라이브러리와 프레임워크, 적용 기준 | 프레임워크와 라이브러리의 제어권 차이 |
| 2 | 싱글톤 패턴의 원리와 장단점 | 단일 인스턴스, 전역 상태, 결합도, 동시성 | 싱글톤의 단점과 사용 시 주의점 |
| 3 | 싱글톤 구현 방식 비교 | 강의에서 다룬 일곱 구현 방식의 초기화 시점, 스레드 안전성, 복잡도 | 구현 방식 선택 기준 |
| 4 | 팩토리 패턴과 이터레이터 패턴 | 객체 생성 분리와 순회 방식 캡슐화 | 변경에 강해지는 이유 |
| 5 | DI·DIP와 전략 패턴 | 의존성 주입, 의존성 역전, 전략과 컨텍스트 | 전략 패턴과 DI의 차이 |
| 6 | 옵저버 패턴과 프록시 패턴 | 상태 변경 통지와 접근 제어 | 두 패턴의 목적, Spring AOP와 프록시 |
| 7 | MVC·MVP·MVVM과 Spring MVC | 표현 계층의 책임과 의존 관계, Spring 적용 | 세 패턴의 차이와 MVC의 장단점 |
| 8 | Flux 패턴과 디자인 패턴 총정리 | 단방향 데이터 흐름, MVC 비교, 전체 패턴 선택 기준 | 상황별 패턴 선택과 종합 질문 |

글 4와 글 6은 서로 다른 두 패턴을 다루지만 강의 분량이 짧다. 두 패턴을
억지로 같은 종류로 설명하지 않고, 각각의 해결 문제를 독립된 절로 구성한 뒤
마지막 비교표에서 목적과 구조의 차이를 명확히 한다.

## 5. 글 템플릿

모든 본문은 아래 순서를 기본으로 사용한다. 패턴 특성상 필요 없는 절은
생략할 수 있지만, 핵심 요약과 면접 질문은 유지한다.

1. **핵심 요약**: 글 전체를 세 문장 이내로 요약
2. **해결하려는 문제**: 패턴 없이 구현했을 때 생기는 문제
3. **구조와 동작**: 참여 객체와 요청 또는 데이터의 흐름
4. **간단한 예시**: Java 또는 Spring 기반의 최소 코드
5. **장점과 한계**: 적용 효과와 오용 시 비용
6. **비슷한 개념과 비교**: 혼동하기 쉬운 패턴이나 원칙 비교
7. **기술면접 질문**: 질문 2~4개와 30초 내외의 모범 답변
8. **복습 체크리스트**: 스스로 설명할 수 있어야 하는 항목
9. **출처**: 해당 Inflearn 강의와 필요한 보충 자료 링크

본문은 코드와 표를 제외하고 약 1,500~2,500자 범위를 목표로 한다. 개념이
충분히 설명되었다면 분량을 채우기 위한 예시나 반복 설명은 추가하지 않는다.

## 6. 메타데이터와 탐색

각 글은 기존 콘텐츠 스키마를 따르는 frontmatter를 사용한다.

```yaml
title: 싱글톤 패턴의 원리와 장단점
description: 싱글톤이 해결하는 문제와 전역 상태, 결합도, 동시성 측면의 한계를 정리합니다.
contentType: study
publishedAt: 2026-08-10
tags: [Design Pattern, Singleton, Java]
series: CS 지식의 정석 - 디자인패턴
topic: Design Pattern
difficulty: intermediate
sidebar:
  order: 2
```

`sidebar.order`는 연재 순서와 동일하게 지정한다. 게시일은 실제 작성 또는 공개
날짜를 사용하며, 미완성 글은 `draft: true`로 공개 대상에서 제외한다.

## 7. 출처와 콘텐츠 경계

- 각 글 하단에 과정명과 해당 강의 단위 링크를 표시한다.
- 강의 문장을 연속해서 인용하거나 자막·교안 내용을 재배포하지 않는다.
- 설명, 표, 코드, 면접 답변은 개인 학습 관점에서 새로 작성한다.
- 강의 내용과 개인 해석이 섞일 때는 `정리` 또는 `실무 관점`임을 구분한다.
- 구현 세부 사항이 언어나 프레임워크 버전에 좌우되면 공식 문서로 검증한다.

## 8. 검증

글 작성이 끝나면 다음을 확인한다.

- `npm run verify`가 성공한다.
- Study 인덱스, 연재 허브, 이전·다음 글 링크가 모두 연결된다.
- 8편의 제목, `sidebar.order`, 연재 목록 순서가 일치한다.
- 모바일과 데스크톱에서 표와 코드 블록이 가로 레이아웃을 깨지 않는다.
- 각 글에 핵심 요약, 장단점, 면접 질문, 출처가 포함된다.
- 강의 표현을 그대로 복제한 긴 구간이 없다.

## 9. 완료 기준

- 디자인패턴 연재 허브와 본문 8편이 `Study`에서 탐색 가능하다.
- 각 글은 독립적으로 읽어도 중심 개념을 이해할 수 있다.
- 독자는 각 패턴의 목적, 대표적인 장단점, 비교 포인트를 자신의 말로 설명할
  수 있다.
- 기술면접 질문에는 정의뿐 아니라 적용 조건과 트레이드오프가 포함된다.

## 10. 제외 범위

- GoF 23개 패턴 전체 설명
- 강의 교안 또는 자막의 재배포
- 완전한 실행형 샘플 프로젝트 제작
- 디자인패턴과 직접 관련 없는 네트워크, 운영체제, 데이터베이스 섹션 작성
