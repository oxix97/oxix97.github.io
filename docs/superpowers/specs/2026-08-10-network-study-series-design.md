# 네트워크 기초 학습 연재 설계

## 목적

Inflearn `CS 지식의 정석` 네트워크 섹션의 40~45강을, 하나의 질문에 함께 답하는 개념 단위로 3편의 기술 블로그 글로 정리한다. 독자가 용어를 암기하는 데 그치지 않고 성능 측정, 장애 범위, 통신 방식의 선택 기준을 백엔드 운영 관점에서 설명할 수 있게 하는 것이 목표다.

## 범위

### 추가할 허브와 글

- `src/content/docs/study/network/index.md`: 연재 소개와 읽는 순서
- `src/content/docs/study/network/network-performance-metrics.md`: 40강을 다루며 트래픽, 대역폭, 처리량, RTT가 실제 API 지연과 어떻게 구분되는지 설명
- `src/content/docs/study/network/topology-and-bottlenecks.md`: 41~43강을 다루며 다섯 토폴로지와 병목 분석 순서를 비교
- `src/content/docs/study/network/network-classification.md`: 44~45강을 다루며 전달 대상과 통신 범위라는 독립적인 두 분류 기준을 설명

### 수정할 기존 페이지

- `src/content/docs/study/index.md`: 네트워크와 웹 항목에 새 연재 링크를 추가

## 정보 구조

연재 허브 제목은 `CS 지식의 정석 - 네트워크`로 하고, 디자인 패턴 연재와 동일하게 강의 순서에 따른 읽기 목록을 제공한다. 세 글은 모두 `contentType: study`, `series: CS 지식의 정석 - 네트워크`, `topic: Network`, `difficulty: intermediate`, `publishedAt: 2026-08-10`과 순서형 `sidebar.order`를 사용한다.

각 글의 마지막 줄에는 이전 글, 연재 목록, 다음 글을 연결한다. 첫 글은 연재 목록과 다음 글만, 마지막 글은 이전 글과 연재 목록만 표시한다.

## 콘텐츠 원칙

각 글은 아래 순서를 지킨다.

1. `핵심 요약`에서 글이 답하는 질문과 가장 중요한 구분을 먼저 제시한다.
2. 정의를 표와 예시로 비교하고, 혼동하기 쉬운 개념을 명시적으로 구분한다.
3. REST API, gRPC, Kafka, API Gateway, Load Balancer, PostgreSQL 등 백엔드 시스템의 관측·장애 분석 맥락으로 연결한다.
4. `기술면접 질문`에는 2~4개의 질문을 두고, 각 답변을 정확히 세 문장으로 작성한다.
5. `복습 체크리스트`와 `참고 자료`로 학습과 출처를 마무리한다.

외부 통신 지연은 네트워크만의 문제로 단정하지 않는다. 애플리케이션 처리 시간과 네트워크 왕복 시간을 분리해 측정해야 한다는 점을 첫 글에 명시한다. Kafka 소비자 그룹의 메시지 분배는 네트워크 계층의 IP 멀티캐스트와 다르므로, 세 번째 글에서 이를 구분한다.

## 글별 구성

### 1. 대역폭이 넓어도 느릴 수 있는 이유: 트래픽·처리량·RTT의 차이

40강(단원 ID `121330`)을 다룬다. 트래픽·대역폭·처리량·RTT 비교표, 대역폭 대비 실제 처리량이 낮아지는 요인, API 응답 시간을 네트워크와 애플리케이션 구간으로 나누는 진단 흐름을 포함한다.

### 2. 연결 구조가 장애 범위를 결정한다: 네트워크 토폴로지와 병목 분석

41~43강(단원 ID `121331`, `121332`, `130662`)을 다룬다. 버스·스타·트리·링·메시형을 구조, 장점, 주요 위험으로 같은 기준에서 비교한다. 요청 경로를 그리고 공통 노드의 지연시간·오류율·자원 포화·큐 적체를 확인한 뒤 확장 또는 분산 방법을 비교하는 병목 분석 순서를 제시한다.

### 3. 유니캐스트부터 WAN까지: 네트워크를 구분하는 두 가지 기준

44~45강(단원 ID `164725`, `130855`)을 다룬다. 유니캐스트·멀티캐스트·브로드캐스트는 전달 대상, LAN·MAN·WAN은 연결 범위라는 서로 독립적인 기준임을 중심으로 설명한다. 일반적인 REST API와 gRPC 요청은 유니캐스트 관점으로 설명하고, Kafka와 IP 멀티캐스트를 혼동하지 않도록 한다.

## 검증

- 네트워크 연재 전용 Vitest 콘텐츠 계약을 추가해 허브 링크·읽기 순서·Frontmatter·필수 섹션·강의 참고 링크·내비게이션을 검증한다.
- 전체 `npm test`, `npm run check`, `npm run build`, `npm run verify:build`를 실행한다.

## 제외 범위

TCP/IP 계층, 라우팅, IP 주소, HTTP 프로토콜 등 46강 이후 내용은 이 연재에 포함하지 않는다. 현재 프로젝트의 실제 인프라 구성이나 성능 수치를 주장하지 않으며, 예시는 일반화된 백엔드 요청 경로로만 사용한다.
